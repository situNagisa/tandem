## 逐任务记录

### 1. 新手上手与第一个 bug

- 上手引导只有在 `hosts.length === 0` 时自动出现；通过带 token 的链接进入后本机已连接，引导不会出现。命令面板里可以“重新看上手引导”，但第一次用的人不会知道。
- 引导第 3 步的“开始第一个会话”只关掉引导，不会把输入焦点交给输入框，仍要自己点一下输入框。
- 设置工作目录后，环境条的分支按钮只显示“分支”两个字，约 1.5 秒后仍为空（会话创建后才显示 `main`）。在任务 3、4 中重复出现。
- 默认权限下 `npm test` 需要审批。审批卡出现时没有声音或桌面通知；我切去别处 1 分钟回来才发现。
- 审阅面板：文件列表在右上，diff 从半屏处才开始，中间约 300px 空白；长行被右边缘截断，横向滚动不明显。
- 提交流程清楚（填写提交信息 → “提交 2 个文件” → 确认对话框 → 提交并关闭）。
- 质量观察：agent 为修复“默认 list 应只显示未完成”把 `list(filter)` 改成 `filter === "all"` 也走未完成过滤，`task list all` 从此只显示未完成；4 个测试仍全部通过。改动审阅没有提示这类语义回归。

### 2. 任务看板

- 创建看板、AI 拆分、把 2 张草稿卡建到待办都顺畅；拆分结果有依赖关系（文档卡依赖实现卡）。
- 卡片放行后，进度显示“当前活动 / 等待允许 Bash”，卡片自动进入“待审批”列；点“去处理审批”能打开对应会话并出现审批卡。这一段体验完整。
- 审批通过后卡片直接进入“完成”，没有经过“待评审”；设置里“完成后需确认”只对拆分草稿中的第二张卡生效。
- 已完成卡片的详情抽屉只有“放行 / 编辑 / 删除”，没有“打开会话 / 查看改动 / 测试结果”，无法核对它改了什么。
- 顶部“合并”一键执行，无确认、无 diff 预览、无“将要合并哪些卡”的列表；本次直接产生 squash 提交 `Squash merge tandem/board-...`。
- 合并后第二张文档卡从“待办”解除依赖，但第一张卡的完成摘要里只有“2 个文件 +39 −5”，看不到分支名/提交号。

### 3. 手机视口与收件箱

- 手机首页把“新会话 / 收件箱”做成顶部分段按钮，“派单”在右上方，入口清楚。
- 派单对话框字段完整（主机、目录、账号、分组/模型、权限、任务），发送后提示“已派单到 本机 · 查看”，不跳页，符合文案。
- 收件箱顶部“待审批”卡有“允许 / 拒绝 / 打开会话”；任务描述被截成一行，命令 `npm test` 单独展示。
- “最近”列表把每次“运行命令 / 已允许 · Bash / 已允许 · Edit”都列为事件，一次任务会产生 4–5 行；真正的“回合完成”被夹在中间，任务多时要翻很久。
- 审批后约 4 秒出现“回合完成”，点它能打开对应会话看到 `npm test` 输出与回答，任务进度闭环成立。
- 环境条上的“分支”仍无分支名；手机上“Worktree”只剩一个无标签开关，第一次用不知道是什么。

### 4. 应用预览

- 从“更多 → 应用预览”打开，自动识别只列常见端口，本地 5189 不在列表，必须手动输入地址。识别区写着“还不会自动识别到本地应用”，与上方仍列出 6 个候选端口自相矛盾。
- 打开后是全屏 modal + 背景遮罩：聊天输入框和发送按钮被盖住，无法在选中元素后直接描述修改；只能关掉预览再输入，此时又看不到选中的元素。
- 点选元素准确：显示“已选 `<h1>` 一杯手冲，留给山里的午后。”，作为上下文附加；发送后 agent 正确修改了 `index.html`。
- 修改被审批后，重新打开预览显示“已根据 1 处改动刷新”，标题字号与颜色都变化，自动刷新可用。
- 关闭预览再重新打开（期间路由回到首页）后，预览显示空白引导页，地址与上次画面没有恢复；同一会话内状态不一致。

### 5. 长会话

- 4 轮后轮次条出现；悬停约 1 秒展开 280px 半透明大纲，第 1–4 轮可点，右侧“第 2/4 轮”随选择更新。行文本被截断（“把选中的 h1 主标题颜色改成…”），但没有 tooltip 显示全文。
- 搜索“咖啡”能命中当前会话中的用户消息，显示片段与“本机 · Tandem · site”，点击可跳转。
- 上下文面板数据完整（系统提示 / 工具定义 / 对话 / 工具结果 / 剩余、最占空间、缓存命中率、读/写），但面板盖住对话内容；底部“压缩上下文（/compact）”在 2552 宽下要滚动面板才完全露出。
- 点“压缩上下文”没有确认，整段对话立即折叠成一行“已压缩上下文 · 节省 1k tokens”。展开箭头很小，第一反应是记录丢了。
- 模型菜单可切换 Gpt 6 Sol + 思考强度“中”，按钮文字变为“Gpt 6 Sol 中”；切回 Luna 后文字不再显示“关”，一致性略弱。
- 两个模型的副标题都是“单价未知”，无法判断成本。
- 反馈模式下点模型选择器不会弹出反馈编辑器；之后点页面其它元素也失效，必须退出反馈模式重进。导出包记录了 3 次 `Uncaught TypeError: Failed to execute 'contains' on 'Node'`，时间正好对应这几次操作。

## 最影响体验的 5 个问题

1. **应用预览挡住聊天输入框**：预览的核心用途是“选中元素 → 描述修改”，但选完元素无法直接输入，必须先关预览，选中上下文又看不见了。
2. **看板“合并”一键直接进 main**：没有确认、没有 diff、没有待合并卡片列表；误点即产生合并提交。
3. **已完成卡片无法核对结果**：详情抽屉没有打开会话/看改动/测试结果入口，只能看到“2 个文件 +39 −5”，不敢放心合并。
4. **反馈模式在模型菜单上卡死**：点模型选择器后不弹编辑器、后续点选失效，并抛 `contains` TypeError；反馈闭环本身被阻断。
5. **手动压缩无确认且历史瞬间消失**：整段对话折叠成一行，只有很小的箭头；用户第一反应是记录丢了。
