# 输入框与消息区 Markdown 设计（规范 + 原型 + 拆分）

> 更新：2026-11-11。一次性设计记录，写完即冻结。状态：草案，三个方向性选择待产品经理拍板（第 9 节打分卡）。
> 本任务只产出设计与原型截图，未改产品代码。原型在 worktree 内截图后已还原，截图存放于 `/tmp/mdshots/shots/` 与 `/tmp/scorecard-md/`，不入库。
> 产品依据（用户原话，2026-11-11）：“输入框的Markdown格式、Markdown显示这些需要详细设计一下，现在是有点草草了事的感觉，看起来非常的Demo”。参考对象：Claude Code Desktop / claude.ai 的输入框与消息排版、Notion/Linear 的行内 Markdown 编辑、GitHub 评论框。

## 0. 摘要

- 现状的核心问题不是“没做 Markdown”，而是**把代码高亮的强调色直接搬进了正文**：标题紫、列表橙、围栏红、链接蓝、@ 路径蓝。正文因此像 IDE 预览，而不是一个安静的输入框（违反 P02“几乎无彩色”）。
- 另一个核心问题是**输入框与消息区各有一套排版**：输入框 15px/1.6、消息 14.5px/1.68；行内代码一边 0.92em+描边+蓝字、一边 0.86em+无描边；代码块一边逐行色带、一边整块；用户气泡完全不渲染 Markdown。读起来“像两个产品”。
- 设计方向：**一层中性排版 + 一处例外（代码高亮）**。输入框保留源码编辑，但所有标记符统一为中性淡化色；消息区把用户气泡也按轻量 Markdown 排版；代码块给出常显语言标签与可发现的复制入口。
- 三个方向性选择均推荐 A：
  1. 输入框标记符：**淡化显示**（符号仍可见、可编辑，统一 58% 中性色）。
  2. 代码块：**静默头部**（语言标签常显、复制/换行悬停出现、1px 边框）。
  3. 用户气泡：**完整轻量渲染**（展示渲染结果，编辑时回落到源码）。
- 拆分 6 个可独立交付的任务（第 10 节），T1 是共享样式层，必须先合。

## 2. 设计原则（本设计新增的可执行规则）

1. **正文只用中性色。** 输入框与消息正文中，除代码块的语法高亮（P04 明确例外）外，不出现 `--syn-*`、`--t-accent*`、`--ctx-*`。标记符、列表符号、链接、@ 标记、任务复选框全部走中性灰。
2. **一套排版。** 输入框、用户气泡、助手正文共用同一组字号/行高/间距（第 3 节），差异只允许来自容器（气泡 padding、输入区可编辑）。
3. **符号让位内容。** Markdown 标记符保留可编辑，但字重 400、颜色 ≤ 58% 的 tertiary；内容用字重、字号、留白建立层级。
4. **代码块是一张卡片。** 有边界、有语言、有复制；宽度=正文列，内部滚动（P13）。
5. **渲染不改变发送内容。** 输入框发送仍是原始 Markdown；用户气泡渲染只发生在展示层，编辑回落到源码。
6. **辅助操作默认隐藏，内容元信息常显。** 时间/操作沿用 P11；代码语言标签是内容元信息，常显；复制/换行是操作，悬停/聚焦出现，触屏常显。

## 3. Token 与排版基线

只用现有 token；在 `styles/chat.css` 顶部新增一组 **Markdown 语义别名**（不是新色板）：

```css
:root, html.dark {
  --md-marker: color-mix(in srgb, var(--t-text-tertiary) 58%, transparent);
  --md-marker-strong: var(--t-text-tertiary);
  --md-inline-code-bg: var(--t-code-bg);
  --md-inline-code-border: var(--t-code-border);
  --md-block-bg: var(--t-code-block-bg);
  --md-block-border: var(--t-border);
  --md-quote-bar: var(--t-border-strong);
  --md-thead-bg: color-mix(in srgb, var(--t-surface-2) 32%, transparent);
  --md-link-decoration: color-mix(in srgb, var(--t-text-secondary) 40%, transparent);
}
```

> 说明：`--md-marker` 与 `--md-thead-bg` 是用现有 token 的 `color-mix` 派生值；若评审要求“不新增任何变量”，可内联复用，但会让 10 处以上重复，建议保留这一层语义别名。

## 4. 输入框规范

### 4.1 定位

输入框是 **Markdown 源码编辑器**：发送原始文本、光标落在源码上、可直接改符号。就地渲染只负责“看得懂”，不负责“藏起来”。因此不做富文本块、不做所见即所得。

### 4.2 标记符号显示策略：选 A 淡化显示

| 方案 | 行为 | 优点 | 缺点 |
|---|---|---|---|
| 现状 | 符号可见，但标题紫、列表橙、围栏红、链接蓝 | 语法一眼可辨 | 彩色符号抢正文，最像 Demo；违反 P02 |
| **A 淡化显示（推荐）** | 符号始终可见、可编辑；统一 0.9em、400、`--md-marker`（58% tertiary）；内容用字重/字号建立层级 | 光标映射与源码选择稳定；不隐藏任何可编辑内容；视觉噪音最低；与 GitHub/Claude 的源码编辑心智一致 | 仍能看到符号（但这是源码编辑器的诚实性） |
| B 光标离开隐藏 | 非光标行隐藏 `#`、`-`、`**` 等，光标进入该行再显示 | 最接近 Notion，静态最干净 | 点击隐藏符号所在位置会产生“点空”感；跨行选择、复制、光标偏移都更难解释；与“源码编辑”定位冲突 |
| C 始终中性显示 | 符号可见、100% tertiary，不加粗、不彩色 | 比现状安静 | 符号仍与内容同权重，长文本里显得碎；与 A 只差透明度，收益小 |

**理由**：A 在不改变既有行为（反馈8#02/1323#05 明确“标记符本身仍可见、可编辑”）的前提下，解决了 90% 的“Demo 感”；B 是方向性改变，需要单独拍板，且会引入光标与选择的新问题，不建议本轮做。

### 4.3 各元素规范

| 元素 | 渲染 | 规范 |
|---|---|---|
| H1–H6 | 整行 | 标记 `#{1,6} + 空格` 用 `--md-marker`；内容 600；H1 16px，其余 15px；不做彩色、不做衬线 |
| 普通段落 | 源码行 | 15/1.65；不加段落 margin；空行保留整行高度（用户主动留白） |
| 无序列表 | 行级 | 标记 `-`/`*`/`+` 用 `--md-marker`，等宽数字；悬挂缩进 1.6em；第二行与文字左缘对齐；嵌套每层 +1.6em |
| 有序列表 | 行级 | 序号 `1.`/`1)` 用 `--md-marker`，`font-variant-numeric: tabular-nums`，右对齐到 2ch，保证 9/10 对齐 |
| 任务列表 | 行级 | `[ ]`/`[x]` 用 `--md-marker`；不画复选框（源码仍可编辑）；消息区才画 |
| 引用 | 行级 | `>` 淡化；左边线 2px `--md-quote-bar`；文字 `--t-text-soft`；不给整行底色 |
| 代码围栏 | 行级 | 开/闭围栏都用 `--md-marker`，等宽；围栏内代码 13/1.6 等宽；整块共享 `--md-block-bg`，首尾行圆角 6px，中间行不加圆角，形成一张连续卡片；块左右不超出正文列（P13） |
| 行内代码 | 片段 | 0.88em 等宽；`--md-inline-code-bg` + 1px `--md-inline-code-border`；文字 `--t-text`（不再用 `--syn-string`） |
| 粗体 / 斜体 / 删除线 | 片段 | 标记淡化；内容 600 / italic / line-through + `--t-text-soft` |
| 链接 | 片段 | 拆成三段：`[`、标签、`](url)`。标签 `--t-text-secondary` + 40% 下划线；`[`、`](url)` 用 0.82em `--md-marker`；URL 过长时中间省略（保留完整 `title`） |
| 分割线 | 行级 | `---`/`***`/`___` 用 `--md-marker`，不加 1px 线（编辑态保持源码行高）；消息区才画线 |
| 表格 | 源码级弱化 | 不做列对齐渲染；`|` 用 `--md-marker`；表头行内容 600；理由：编辑态列宽随输入变化，强行排版会抖动，且提示词里表格少 |
| @ 路径标记 | 不可拆片段 | 0.92em 等宽、`--t-text-secondary`；底 `--t-bg-subtle`、1px `--t-border`、圆角 4px、padding 0 4px；前置 12px 文件/文件夹图标；悬停 `title` 显示完整路径；不再用 `--syn-attr` 蓝 |
| 粘贴长文本 | 胶囊 | 阈值改为 **> 600 字或 > 8 行**；胶囊高 28px、圆角 6px、边框 `--t-border`、文字 12px；`FileText` 图标 + “粘贴的文本 · N 行” + 字数；发送时展开到原文位置 |
| 图片附件 | 缩略图 | 56×56，圆角 8px，1px `--t-border`，object-contain；悬停显示文件名/大小；点击打开大图；右上角删除按钮悬停出现（触屏常显） |

### 4.4 代码块在输入框里的实现约束

- `parseEditor` 增加块级信息（`blockStart` / `blockEnd` / `lang`），渲染层把同一围栏内的行标记为 `data-code-block`，CSS 用首/中/尾选择器拼出连续背景；不要靠每行 `margin-inline: -4px` 拼。
- 围栏行仍是可编辑文本；语言名 `ts` 用 `--md-marker`，光标可进入。
- 代码块内不跑语法高亮（输入框不是代码查看器；高亮会再次引入彩色噪音）。
- 块内 Tab 插两个空格；块内 Enter 只换行；块内 `Ctrl/Cmd+Enter` 仍然发送（显式逃生口）。

### 4.5 键盘行为

| 键 | 普通行 | 列表行 | 代码块内 |
|---|---|---|---|
| Enter | 发送 | 续号/续项；空项退出列表 | 换行，不发送；在开围栏行回车自动补 `\n\n```\n`，光标停在空行；在闭围栏行回车在其后新起一行 |
| Shift+Enter | 换行 | 换行（不续项） | 换行 |
| Ctrl/Cmd+Enter | 发送 | 发送 | 发送 |
| Tab | 让焦点离开（保留键盘可达性） | 行首缩进 +2 空格 | 插入 2 空格 |
| Shift+Tab | 焦点后退 | 行首缩进 −2 空格 | 行首缩进 −2 空格（若有） |
| Backspace | 删除字符 | 光标在标记后第一格时先删标记、保留文字 | 行首删 2 空格缩进 |
| Escape | 关闭补全/菜单 | 同左 | 同左 |
| ↑/↓ | 补全打开时移动选中项 | 同左 | 同左 |

- 补全打开时 Enter 只选中补全项，不发送；补全项为空（加载中/无匹配）时 Enter 仍发送——这条要在实现里显式判断 `items.length > 0`。
- 发送后清空输入、保留草稿恢复；草稿恢复时不重新解析出彩色样式。

### 4.6 粘贴与拖放

1. 剪贴板有图片 → 作为附件，不插入文本（现有行为）。
2. 有 `text/plain` → 优先纯文本，按 Markdown 源码插入；超过阈值折叠成胶囊。
3. 只有 `text/html` → 做白名单转换：`h1–h6`→`#`、`ul/ol/li`→列表、`strong/em/code/a/pre`→对应 Markdown；其余标签取文本；转换结果仍是源码。转换失败则退化为纯文本。
4. 拖入图片 → 附件；拖入文件 → 插入 @ 路径标记（若可解析），否则插入文件名文本。
5. 不把 HTML 的 class/style/inline style 带进 contenteditable；粘贴后统一走 `readText` 回读，避免 DOM 结构漂移。

### 4.7 中文输入法约束

- 组字期间（`compositionstart` → `compositionend`）不重绘编辑区；现有 `composingRef` 保留，并补一条：`onKeyDown` 在 `e.nativeEvent.isComposing || keyCode === 229` 时直接返回，不执行 Enter 续号/发送、不执行 Tab 缩进。
- 组字文本不套 `ce-path` 等胶囊样式（现有 `data-composing` 已处理 @ 标记，扩展到所有片段样式）。
- `compositionend` 后只做一次 `onChange`，光标停在组字结束位置；不 trim、不补空格、不自动续列表。
- 候选窗位置依赖 DOM 文本节点；不要在组字期间 `replaceChildren`，否则候选窗会跳到左上角。
- 输入框达到 `max-height: 40vh` 后，组字行保持在可视区内（滚动到光标），滚动不要触发补全面板重新定位。

## 5. 消息区规范

### 5.1 用户气泡：选 A 完整轻量渲染

| 方案 | 行为 | 评价 |
|---|---|---|
| 现状 | 源码原样 + `pre-wrap` | 最像 Demo；发送后看不到排版结果 |
| **A 完整轻量渲染（推荐）** | 展示层用 Markdown 渲染；标题降为 15px/600；列表悬挂缩进；代码块卡片化；编辑时回落到源码 textarea | 与助手正文同一视觉语言；用户能确认发出去的样子；编辑仍可控 |
| B 只渲染行内 | 只处理粗体/斜体/行内代码/链接，块级保留源码 | 改动小，但列表/围栏仍是一坨源码，Demo 感只去掉一半 |
| C 保持源码但换等宽 | 气泡内用 13px 等宽显示 | 明确“这是源码”，但和助手排版割裂，且长文更难读 |

**理由**：用户发送的内容是给人读的，不是给编译器读的；展示层渲染不改变存储与编辑（复制消息仍复制 Markdown 源码），风险可控。A 与 B 的差异只在块级元素，A 的实现成本主要是复用现有 `Markdown` 组件加一个 `variant="user"`。

### 5.2 用户气泡排版

- 容器：右对齐，`max-width: 80%`，`bg: --t-bg-subtle`，圆角 14px，padding 10px 16px，15/1.65，`break-words`。
- 段落：margin 0.45em 0，首尾 0；不使用 `pre-wrap`（源码换行由 Markdown 语义决定）。
- 标题：一律 15px/600，不上 22/17（气泡不是文章）；H1–H6 视觉合并为“粗体小标题”。
- 列表：`padding-left: 1.35em`，`li` 0.18em，悬挂缩进；有序数字 tabular。
- 代码块：复用消息代码块组件，但 `max-height: 320px`、字号 12px、头部 26px；宽度 100%，内部横滚。
- 行内代码：0.88em、`--md-inline-code-bg`、1px 边框、正文色。
- 引用：2px 左边线、`--t-text-soft`、padding-left 0.8em。
- 表格：13px，内部横滚；气泡内不铺满视口，`max-width: 100%`。
- 任务列表：复选框 13px；选中态用 `--t-text-secondary` 勾 + `--t-bg-active` 底，不用橙色。
- 图片：附件缩略图在文字上方（现有），圆角 10px、1px 边框；点击查看。
- 编辑态：点击“编辑并重发”后，气泡原位换成 textarea，字号 15/1.65（与气泡一致），显示原始 Markdown；宽度沿用气泡（P12）；不实时渲染。

### 5.3 助手正文

- 阅读列：沿用 `max-w-[808px]`；正文 15/1.65；段落 0.75em。
- 标题：22 / 17 / 15 / 14.5，600，行高 1.35，上 1.5em 下 0.55em；首个元素上边距 0（现有）。
- 列表：左 1.35em，项 0.28em，标记 `--t-muted`，数字 tabular；嵌套每层 +1.35em。
- 引用：2px `--md-quote-bar`，`--t-text-soft`，padding-left 0.95em，段落 margin 0.35em。
- 链接：`--t-text-secondary` + 40% 下划线；悬停转 `--t-text`；外链新窗口。文件引用继续用 12px `FileText` 图标 + 0.88em 等宽。
- 行内代码：0.88em、`--md-inline-code-bg`、1px `--md-inline-code-border`、正文色、圆角 4px。
- 分隔线：1px `--t-border`，上下 1.6em。

### 5.4 代码块（消息区）

选 A 静默头部。结构：

```

│ ts                                     复制 换行 │  ← 30px，语言 12px tertiary，操作悬停出现
├──────────────────────────────────────────────┤
│ export function parseEditor(...) {           │  ← 12.5/1.65，padding 10 14 12
│   ...                                        │
└──────────────────────────────────────────────┘
```

| 方案 | 行为 | 评价 |
|---|---|---|
| 现状 | 无边框、无标签；标签/复制/换行在右上悬浮，悬停出现 | 静态看什么都没有；滚动后入口消失 |
| **A 静默头部（推荐）** | 1px 边框 + 8px 圆角；语言标签常显（没有语言时显示“文本”）；复制/换行悬停或聚焦出现，触屏常显；头部不随内容滚动 | 语言可发现、操作不抢眼；符合 P11“辅助信息默认隐藏”的例外边界 |
| B 完整工具条 | 语言 + “自动换行” + “复制代码”文字按钮常显，头部加分隔线 | 最可发现，但每个代码块都多一行操作，长回复噪音大 |
| C 角标 + 悬浮复制 | 无头部，左上角 `ts` 小角标、右上角复制图标，正文 padding-top 24 | 最轻，但角标与代码第一行争空间，长语言名会挤 |

- 语言来源：围栏信息字符串；未写时显示“文本”（不猜）；代码高亮仍可自动识别，但标签显示真实来源，避免“标签说 js、高亮是 ts”的错位。
- 复制：复制代码正文（不含围栏）；成功后图标变勾 1.5s。
- 自动换行：沿用现有开关与 `localStorage['tandem.codeWrap.v1']`；开启后行号/代码逐行对齐（文件预览已有 grid 方案，消息区可复用）。
- 横向滚动：宽度=正文列，块内滚动；右侧渐隐 + “左右滑动”提示（现有）；不做负外边距。
- 最大高度 420px，超出内部滚动；流式时先纯文本、结束后高亮（现有）。

### 5.5 表格

- 字号 13/1.6；`width: max-content; min-width: 100%`；块内横滚。
- 表头 12/600 `--t-text-secondary`，底色 `--md-thead-bg`；表体行底透明；行间 1px `--t-border`，最后一行无底线。
- 单元格 6px 10px；保留 GFM 对齐：把 `align` 属性映射为 `text-align`，不要用全局 `left` 覆盖。

- 横向溢出时显示渐隐与“横向滚动”提示（现有 `useHorizontalOverflow`）。

### 5.6 任务列表与复选框

- 复选框 13px，1px `--border`，圆角 3px，背景透明；选中：`--t-bg-active` 底 + `--t-text-secondary` 勾；不用 `accent-color`（避免橙色）。

## 7. 与 design.md 原则的对应

| 原则 | 本设计如何落实 |
|---|---|
| P01 温暖、安静、克制 | 正文去掉彩色语法；标记符淡化；代码块只保留一处低饱和高亮 |
| P02 几乎无彩色 | 输入框/气泡/正文不使用 `--syn-*` 与 `--t-accent*`；橙色只留发送/品牌/待审批；任务框改中性 |

| P04 例外色只限明确区域 | 代码高亮只出现在代码块；输入框不做高亮，避免“例外扩散” |
| P05 文字够亮够大 | 正文统一 15px；辅助 ≥12px；标记符虽淡化但内容对比度不降 |
| P06 字体字重固定 | 正文 400、标题 600、代码等宽；不引入 300 细体与衬线 |
| P07 间距/圆角/动效档位 | 4px 基数；代码块 8px、气泡 14px、输入卡 20px；复制反馈 120ms |

| P09 菜单与列表紧凑 | 代码头部 30px；语言、复制单行；不堆说明 |
| P10 弹层稳定 | 表格/代码块横滚只改内部滚动，不改变容器尺寸 |
| P11 辅助信息默认隐藏 | 复制/换行悬停或聚焦出现；语言标签作为内容元信息常显 |
| P12 展开/折叠只改高度 | 编辑态宽度沿用气泡；代码块换行只改高度，不改列宽 |
| P13 宽内容不撑开容器 | 代码块/表格宽度=正文列，内部横滚，无负外边距 |
| P14 参考 Claude Code 的行为与密度 | 源码编辑 + 就地样式；代码块头部语言与复制；消息排版紧凑 |
| P16 一词一概念 | 代码头部用“复制”“自动换行”，不写“复制到剪贴板”等变体 |
| P22 进行中看得见 | 流式光标与计时保持不变；代码块流式阶段纯文本，结束后高亮 |

  4. 粘贴：9 行文本生成胶囊，点击移除后文本不进入输入框；发送时展开为原文。
  5. 宽度：代码块/表格 `offsetWidth` ≤ 正文列 +2px；横向滚动容器内部滚动，页面不出现横向滚动条。

## 11. 不做 / 不改什么

- 不改发送内容与协议：仍然是原始 Markdown 文本；不引入富文本存储。
- 不做所见即所得、不做块级拖拽、不引入第三方编辑器（ProseMirror/Lexical/TipTap）。
- 输入框不做语法高亮、不做表格列对齐、不隐藏标记符（除非 D1 改选 B）。
- 不新增字体；不新增色板；不改变代码高亮的 GitHub Light/Dark 取色。
- 不改消息时间/用量/操作条的默认隐藏策略（P11）。
- 不改用户气泡的右对齐、最大宽度、圆角与背景 token（只改内部排版）。
