# 反馈根因台账

每条用户反馈处理时，先判断它属于哪个**根因**，再决定修法。同一根因第二次出现，就说明只修表面不够，必须在共享层修掉，并加一条自动检查防止再犯。

## 处理规则
1. 每条反馈在回执和提交信息里标上根因编号（如 `R03`）；新根因就在下表新增一行。
2. 根因第 1 次出现：可以就地修，但要记进本表。
3. 根因第 2 次出现（复发）：必须改共享层（统一组件、设计 token、公共工具函数），并加一条自动检查（ui-audit 规则、单测或回归用例），在"防线"一列写明。
4. 每轮发版前看一眼本表：最近 7 天"出现次数"增加的根因，优先排查同类位置。
