# 工作站：客户端-服务模式（替代「工作区 + 账号中心」）

> 更新：2026-11-10。已实现 v1；代测步骤见 [test-guides/workstation.md](test-guides/workstation.md)。

> 2026-11-09 产品所有者定的方向。任何人先向**工作站**注册账号，再**添加自己的主机**，才能开始用；没有单独的「登录账号管理平台」这一步。团队把工作站部署在一台服务器上，个人把本机当服务器；两者是同一个程序的两个可独立开启的角色。

## 1. 角色

同一个 `tandem-host` 程序，两个可独立开启的角色：

- **工作站服务（workstation）**：账号注册/登录、主机登记、授权、连接转发、审计。**不跑 agent**。团队服务器只开这个角色。
- **主机（host）**：执行 agent、会话、工具、设备。桌面端、`tandem-host`、手机连接的都只是主机。

个人模式：一台机器同时开两个角色（桌面端首次引导可一键「把这台电脑作为工作站」）。团队模式：服务器只跑 `tandem-host workstation`，各成员的机器作为主机加入。

所有角色只在内网 / VPN 使用；不做端口映射、公网代理、第三方隧道与推送。

## 2. 客户端流程（桌面 / 浏览器 / 手机一致）

1. **进入先登录**：打开 Tandem（桌面、网页、手机）先看到登录/注册页，未登录时任何路由（含深链）都只显示登录页，地址栏保留原来要去的位置，登录后回到那里。
2. 首次打开：填写**工作站地址**（如 `http://192.168.1.10:8481`）；页面由工作站托管或在本机回环打开时自动填入，个人模式可一键使用这台电脑的工作站。
3. 工作站尚未初始化 → 「创建工作站」：工作站名称 + 管理员用户名/密码。**第一个注册的用户是管理员**。
4. 工作站已初始化 → 注册（内网开放注册，或仅邀请）或登录。
5. 登录后进入「我的主机」：只显示自己添加的、以及别人授权给自己的主机。**账号下没有主机时**主界面显示空状态「先添加一台主机」，新会话入口禁用并说明原因；添加主机后自动出现。
6. 选中主机 → 正常会话界面（侧栏、会话、审批、设备、看板等全部照旧）。

客户端只保存工作站地址与账号令牌；主机地址由工作站下发，用户不手抄主机地址或主 token。登录客户端 ≠ 添加主机：电脑、手机都只是登录入口，执行任务的主机必须显式加入账号。

## 3. 添加主机

客户端「添加主机」（空状态、设置 → 主机、设置 → 工作站、命令面板均可打开）给出**按平台切换的一行命令**（Windows PowerShell / macOS / Linux，分段控件 + 代码块复制）：

```powershell
& ([scriptblock]::Create((irm http://192.168.1.10:8481/install.ps1))) -Token 'ach_…'
```

```bash
curl -fsSL http://192.168.1.10:8481/install.sh | sh -s -- --token ach_…
```

- 命令里是**一次性注册令牌**：15 分钟有效、只能用一次、工作站只存 SHA-256；关闭/重新生成弹层即换新令牌。
- 目标机器执行一次：下载本机主机安装包（由工作站随附，不接公网/第三方）、安装到 `~/.tandem-host/app`，以当前账号身份**持久**连接——Linux `systemd --user`、macOS launchd LaunchAgent、Windows 当前用户的启动项（`HKCU\…\Run`，无需管理员；schtasks 的 ONLOGON 在非管理员会话会「拒绝访问」）；进程退出自动重启、断线自动重连。只想起后台进程时加 `--no-service`。目标机需要 **Node.js ≥ 22**（系统 Node；不用 Electron 顶替，桌面版升级/卸载后主机仍可用）。
- 兑换出的长期凭据（Ed25519 私钥）只存在主机本地 `accounts.json`（0600），不进客户端、不上报工作站。
- 客户端对话框实时显示「等待主机连接… → 已注册 <主机名>，等待上线… → 已连接 <主机名>」，连接后自动同步到主机列表。
- 已装 `tandem-host` 的机器可只执行 `tandem-host join <工作站地址> --token <令牌> --service`；同一台机器对同一工作站重复执行是幂等的。
- 安装包：`scripts/pack-host.mjs` 生成 `packages/server/host-pack/tandem-host.tgz`（Unix）与 `tandem-host.zip`（Windows，安装脚本用 `Expand-Archive`，不依赖 Windows 自带 tar）。只收运行时文件，打包时断言所有路径为 ASCII、包含 `dist/cli.js`，测试夹具/文档/示例/源码映射不会进包。**原生预编译模块按目标平台裁剪**：在 WSL 里打包时 node_modules 里同时躺着各平台的 `.node`，Windows 的 ZIP 只留 `prebuilds/win32-*`、Unix 的 tgz 只留 `linux-*`/`darwin-*`，并断言混入别平台直接失败（R56 复发根因）。
- `tandem-host join` 先确认端口上的 Tandem Host 属于本数据目录（`/api/host` 的 `id` 与本地 `hostId` 一致）：端口被另一个数据目录的实例占着时自动改用下一个空闲端口（7879…），不再拿错令牌去登记得到 401。失败按「崩溃（负退出码）/绑定码/连不上工作站」三类给不同提示。
- 工作站没有随附安装包时，脚本失败并打印**手动安装步骤**（下载、解压、`node dist/cli.js join …`），不会静默失败。

**本机也要显式添加**：桌面端提供「添加这台电脑」一键操作（内部同样走登记 + 绑定），不允许因为「本机就是工作站」而隐式出现。工作站服务自身的 Host 不自动进入任何账号的主机列表。

> 调试版例外：调试版 Host 在回环地址打开时自动拉起本机工作站、登录「调试账号」，并把本机与一台**演示主机**（内置演示模型/会话/设备）登记到该账号；网页与桌面都一样，`TANDEM_DEBUG_ACCOUNT=0` 可显式关闭（回归用）。退出调试账号后记住不自动登录；登录页仍可用「使用调试账号登录」恢复。发布版没有调试登录与演示主机。见 `docs/features/release.md` 第 0 节。

## 4. 连接与加密

- 主机向工作站发起**出站 WebSocket 长连接**（`workstation/tunnel.ts`：`/_tunnel` 注册、挑战签名、`/h/<hostId>/...` 多路复用 HTTP/WS、ACK 流控、断线退避）。主机不需要开放入站端口。
- 工作站登记时绑定 `hostId ↔ 主机公钥`；隧道的挑战签名必须匹配已登记公钥，防止他人冒用 hostId。
- 客户端只连工作站：Host 地址 = `<工作站地址>/h/<hostId>`，指纹来自登记记录。客户端与主机之间走 **E2E**（X25519 + Ed25519 + HKDF + AES-256-GCM，E2E v1），账号令牌在密文内，由主机验签。
- 工作站**能看到**：账号、主机登记信息、谁在何时连了哪台主机、请求次数/大小/时长、在线状态；**看不到**：请求/响应正文、会话内容、文件、命令、账号令牌、模型 Key。
- **模型代理**：模型账号与 Key 属于工作站账号（见 [features/model-accounts.md](features/model-accounts.md)）。主机 agent 发模型请求时用登记私钥签名 POST `/api/workstation/host/model-proxy`（时间戳 + hostId + accountId + 方法 + 路径 + body 哈希，5 分钟有效）；工作站校验签名、账号对主机的访问权与 profile 归属，再用该账号 Key 调上游，NDJSON 流式回传并记账。主机不持有 Key；个人模式（同进程）走进程内直连。
- 工作站只能拒绝/延迟/断开转发（可用性），不能冒充主机（指纹不符会拒绝）或篡改内容（GCM 校验失败即断开）。
- 局域网内客户端与主机可直连时，可选直连（性能优化，v1 不做自动发现；已手工添加的直连主机保留）。

> 威胁边界不变：工作站被攻破 = 可拒绝服务、可伪造账号/授权（进而骗主机接受新令牌），所以工作站只部署在信任的服务器、只在内网；主机侧仍逐请求验签 + 吊销快照。明文 HTTP 的内网窃听边界与团队功能一致。

## 5. 账号、可见性与授权

- 注册：默认**开放注册**（内网任何人可注册）；管理员可改为**仅邀请**。首个注册者为管理员。账号状态 `active/disabled`，吊销即时生效（签名快照推送 + 主机 10s 轮询兜底）。
- **默认安全**：新账号只看到自己添加的主机；别人的主机/设备要主人授权才可见；管理员默认也不获得他人主机会话内容的访问权（只做注册策略与账号管理）。
- 授权模型：主机主人把主机（或其中的项目目录 / 设备）授权给某账号，角色沿用 **所有者 / 协作者 / 审批者 / 观察者**；可随时撤销。项目范围落到主机绝对路径，主机端按「账号 + 本机」计算有效角色，范围外 404，不暴露存在性。
- 设备共享与网关并入同一授权：设备属于主机，授权主机即可按角色使用其设备；网关按账号签发/吊销，账号禁用时联动失效。
- **模型账号同样按账号**：provider 账号、分组、Key、倍率与模型勾选归工作站账号，Key 加密保存在工作站。共享主机时，被授权人开会话使用**被授权人自己的**模型账号；主机主人与管理员的设置页也只看到掩码。设置项跨主机一致，不随「当前主机」变化。
- 旧数据搬迁（一次性）：主机首次以账号身份连接时，把本地 `profiles.json`（含 Key）上传到该主机所属账号，随后删除主机本地文件；同名同协议以工作站已有为准，丢弃主机的。不保留旧的按主机模型账号 API（工作站模式下 `/api/profiles` 返回 410）。
- 审计按账号：注册/登录/失败、主机登记/移除、授权变更、会话与审批（带账号 id）。工作站保留账号与主机级审计；主机保留内容级审计。

## 6. 与现有实现的关系（迁移，不并存两套）

现有 `src/accounts` 的「工作区 + 账号中心」升级为工作站服务，协议/存储/令牌继续复用：

- 原**账号中心 Host** → 工作站服务（`workspace.centerHostId` 保留为工作站标识）；它自身作为工作站服务，不作为主机出现在列表里。
- 原**已加入的 Host** → 工作站上**所有者账号**的主机（`ownerId` = 创建工作站的首个 owner/admin）。
- 旧「加入码」→ 主机绑定码（语义从“加入工作区”变为“把本机登记为某账号的主机”，仍一次性、24h 上限可调）。
- 令牌仍为 `acw_` Ed25519 访问/刷新令牌，新增 `perHost` 声明（每台主机的角色/项目范围）；主机本地验签，不逐次回源。旧令牌无 `perHost` 时按原 role/scope 解释，迁移后逐步自然过期。
- 主 token（Host owner）仍是本机最高权限，用于本机设置与本机工作站加入；成员 token（`tmm_`）、设备令牌（`dvt_`）、网关令牌（`tgw_`）保留，账号禁用/授权撤销时联动。
- 旧「工作区管理」页替换为「工作站」页：主机、成员、授权、注册策略、审计。

## 7. 本地模式（保留）

不加入任何工作站的单机使用保留：地址 + token 直连，全部现有功能不变。但**默认引导走工作站模式**；首次启动桌面端会先问「创建/加入工作站」还是「仅本机使用」。本地模式下仍可在以后随时「把这台电脑作为工作站」或加入别的工作站。

## 8. 远程主机

添加远程主机统一通过工作站的一行命令：登录目标机器（包括经 SSH 登录）后执行 §3 的命令，主机随即可用。SSH 只作为登录手段，密码/私钥不进入工作站。

## 9. 部署

团队服务器（内网 Linux，Node ≥ 22）：

```bash
TANDEM_HOME=/var/lib/tandem-workstation tandem-host workstation --host 0.0.0.0 --port 8481
```

Docker（只发布到内网）：

```bash
docker build -f deploy/workstation/Dockerfile -t tandem-workstation .
docker run -d --name tandem-workstation -p 8481:8481 \
  -v tandem-workstation-data:/data -e TANDEM_HOME=/data tandem-workstation
```

工作站使用独立数据目录（`workstation/accounts.json`，600 权限），不与某台主机的会话数据混放。防火墙只允许公司网段访问 8481；不配置公网反代、不做端口映射。

个人模式：桌面端首次启动 →「把这台电脑作为工作站」→ 本机 Host 内嵌启动工作站（默认 8481，独立数据目录）→ 创建管理员账号 →「添加这台电脑」→ 开始使用。

## 10. v1 范围与以后

**v1 做**：工作站服务独立进程 + 内嵌启动；开放注册/首个管理员/仅邀请；登录、我的主机、添加主机（绑定码 / 主机侧加入 / 本机一键）、授权（项目/角色）、撤销；出站隧道 + E2E 转发；旧数据自动迁移；本地模式不变；CLI `workstation` / `join`；代测文档。

**v1 不做**：多工作站联邦/备用工作站；LDAP/OIDC/SSO；WebAuthn；TLS/mTLS 与请求签名；公网暴露；自动 LAN 直连发现；跨工作站迁移主机；按账号流量配额（沿用网关限额）；**模型请求的短期凭据下发**（每次请求都经主机签名转发；以后若成为性能瓶颈再加）。

**以后**：工作站 TLS + 请求签名；备用工作站只读副本；主机迁移/接管；跨站联邦；按账号的审计导出与告警；WebAuthn/设备密钥登录全面替代密码。

## 11. 验证（开发期自测）

- 只跑工作站：`TANDEM_HOME=/tmp/tandem-ws tandem-host workstation --port 8481`。
- 两台主机：`TANDEM_HOME=/tmp/tandem-ws-h1/2 tandem-host --port 8482/8483`（mock provider），分别绑定到用户 1。
- 两个账号：首个注册者为管理员；用户 2 默认看不到 h1/h2，授权 h2 后才看到。
- 全新客户端只填 `http://127.0.0.1:8481`：先登录 → 主机列表（无主机时空状态）→ 添加主机 → 新建会话 → 流式回复（经工作站转发，E2E）。
- 一行命令：工作站页面/客户端「添加主机」复制命令，在 `/tmp` 的另一个 `TANDEM_HOME` 执行（加 `--no-service`），主机上线、凭据文件 0600；同一令牌再用一次被拒。
- 主机端口不对客户端开放（只访问 8481）仍可用；旧 `accounts.json` 启动后自动迁移；本地模式回归不变。
- 账号与模型：在两台主机上分别配置旧 profiles → 加入工作站后工作站账号只有一份、主机本地 `profiles.json` 被删除且目录里搜不到 Key → 在远端主机会话里发消息，请求经工作站代理到 mock provider 成功 → 主机 `model-usage.json` 按账号记账。
- 自动化：`e2e/regression.mjs`「工作站客户端-服务」用例；Playwright 截图 `/tmp/ws-shots/`；步骤见 `test-guides/workstation.md`。
