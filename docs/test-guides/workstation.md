# 工作站：给产品所有者的代测步骤

> 更新：2026-11-11。设计见 [docs/workstation.md](../workstation.md)。

> 全程在公司内网 / VPN，**不要做端口映射或公网暴露**。工作站机器需要 Node ≥ 22；目标电脑只需能访问工作站，不需要 Node。真实模型 Key 不必配置；登录、主机登记与会话不依赖模型（发消息需要至少一个可用账号）。有问题用反馈模式导出 `.tfb` 发飞书。

## 零、启动与调试版自动登录

- 启动：`npm start`（或 `TANDEM_HOME=/tmp/tandem-ws tandem-host --port 8481`），浏览器打开终端打印的地址（默认 `http://127.0.0.1:8481/`）。
- **调试版**在回环地址打开时自动登录「调试账号」（用户名 `debug`），自动添加本机与演示主机；不用注册。
- 发布版、非回环地址、`TANDEM_DEBUG_ACCOUNT=0`（e2e 模拟发布语义）不自动登录，必须正常注册/登录。
- 调试账号密码在 `<TANDEM_HOME>/debug-account.json`（0600），不要截图或发群；`POST /api/debug/auto-login` 只在调试版注册，且只接受 `127.0.0.1` / `::1`。
- 侧栏底部账号位置显示「调试账号」；账号菜单可退出、用其他账号登录。设置 → 外观有「调试账号自动登录」开关。
- 首个真实注册账号仍是管理员；调试账号不算第一个用户。

## 一、最小流程（一台机器）

1. `npm start`，浏览器打开 `http://127.0.0.1:<端口>/`。
2. 未初始化 → **创建工作站**：工作站名称 + 管理员用户名（3–32 位）+ 密码（≥ 8 位）→ 创建。
3. 登录后账号下没有主机：显示「先添加一台主机」，新会话按钮禁用并说明原因。
4. **添加主机 → 添加这台电脑**：主机列表出现本机（在线），可以新建会话、发一条消息看到流式回复。
5. 刷新页面：本机主机仍在列表里且在线；重启工作站后依旧（数据在 `local-host/`）。

**本机也要显式添加**：运行工作站的这台机器不会自动出现在账号的主机列表里；只有调试版自动添加。

## 二、远端主机（执行器）

服务器（内网 Linux，Node ≥ 22）：

```bash
TANDEM_HOME=/var/lib/tandem-workstation tandem-host --host 0.0.0.0 --port 8481
```

防火墙只允许公司网段访问 8481。也可用 Docker（只发布到内网）：

```bash
docker build -f deploy/workstation/Dockerfile -t tandem-workstation .
docker run -d --name tandem-workstation -p 8481:8481 -v tandem-workstation-data:/data \
  -e TANDEM_HOME=/data tandem-workstation
```

1. 管理员首次打开 `http://<服务器IP>:8481` → 创建工作站。
2. 其他成员打开同一地址 → **注册账号**（默认开放；管理员可改为仅邀请并生成邀请码）。
3. 每台主机（包括管理员自己的电脑）：登录后在「添加主机」里复制对应平台的一行命令，在主机那台机器上执行一次。执行器前台运行，窗口停在「已连接工作站」即正常；加 `--service` / `-Service` 才设置开机自启（下次登录生效）。
4. 服务器本机也在管理员自己的浏览器里点「添加这台电脑」。
5. **可见性**：成员 A 只看到自己添加的主机；A 在「工作站 → 我的主机 → 授权」把主机（可限定目录）授权给 B，角色选 协作者/审批者/观察者；B 刷新后只看到被授权的主机。
6. **手机/新电脑**：只填工作站地址登录，主机列表自动出现，不需要抄主机地址或 token。
7. **吊销**：管理员禁用账号后，该账号请求立即 401，已开的 WS 被断开。

## 三、模型账号

- 账号级：设置 → 账号与模型里配置的 provider/分组/Key 属于工作站账号；所有主机上下文共用，Key 只在工作站（`profiles.json` 加密，`profiles.key` 0600）。
- 在任一主机的会话里发消息，请求经工作站调用上游；用量记在 `<TANDEM_HOME>/model-usage.json`（按账号 + 主机）。
- 在主机目录（`local-host/`、`remote-hosts/<id>/`）里搜不到 Key 明文。

## 四、在 Windows 上代测远端执行器（用户实机）

### 前置条件（Windows）

- Windows 10/11 的 PowerShell（5.1 或 7 都可）。**不需要 Node.js，不需要管理员。**
- 这台电脑能访问工作站地址（例如 `http://<工作站IP>:8481`）。
- 执行器只出站连接工作站，不监听端口；安装在 `%USERPROFILE%\.tandem-executor`，与桌面版的 `%USERPROFILE%\.tandem` 互不影响。

### A. 浏览器（Chrome / Edge）

1. 打开工作站地址，用账号登录；没有主机时显示「先添加一台主机」空状态。
2. 点「添加主机」：弹层默认选 Windows，命令形如 `& ([scriptblock]::Create((irm http://<工作站地址>/install.ps1))) -Token 'ach_…'`。令牌有 15 分钟倒计时。「开机自启」默认关闭，本轮先不勾。
3. 弹层文案应写明目标机器只需能访问工作站、不需要安装 Node.js。

### B. Windows 上执行一行命令（4 步）

1. 在 PowerShell 粘贴执行第 A.2 步复制的命令。
2. 输出应依次显示「正在下载执行器… → 正在校验 sha256… → 正在安装到 …\tandem-exec.exe … → 正在登记本机到 … → 已登记并连接工作站 …，主机 <电脑名>」。窗口停在这一行不退出是正常的（前台运行，关闭窗口即断开）。
3. 回到客户端弹层：应从「等待主机连接…」变成「已连接 <电脑名>」，主机列表出现该电脑。新建会话，让助手「在工作目录写一个 hello.txt 再读回」，应能成功。
4. 关掉 PowerShell 窗口，客户端里该主机应变为离线。再把同一命令执行一次：令牌已用，应提示「绑定码无效、已使用或已过期」并退出（退出码非零）。可选：命令末尾加 `-Service`，执行后 `reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v TandemExec` 能查到启动项。
5. 失败时把窗口里的完整输出回传。常见原因：「无法从 …/executor/windows-amd64 下载」（工作站地址不可达或没有该平台执行器）、「执行器校验失败」（下载内容被改动或不完整）、「绑定码无效、已使用或已过期」（重新生成后再执行）。

### C. macOS / Linux 上执行一行命令

```bash
curl -fsSL http://<工作站地址>/install.sh | sh -s -- --token ach_…
```

前台运行，关闭终端即断开。加 `--service` 设置开机自启（Linux `systemd --user`、macOS LaunchAgent，下次登录生效）。令牌一次性。

## 五、需要回传的信息

- 每一步截图（首次创建工作站、添加主机弹层、主机列表在线/离线、添加这台电脑、授权弹层、用户 B 只看到被授权主机）。
- 哪台机器 / 哪个账号 / 角色；浏览器控制台报错；工作站日志（终端或 `TANDEM_HOME` 同目录）。
- 主机一直离线：确认主机能访问工作站地址、注册令牌未过期、该主机未被其他账号登记（同一 hostId 不能换主人）。

## 六、安全提醒

- 工作站账号密码、绑定码、邀请码不要发到公网群聊或截图。
- `TANDEM_HOME/accounts.json` 含工作站私钥，`profiles.json`/`profiles.key` 含加密模型 Key，按敏感配置对待（0600）；定期备份，怀疑泄露时重建工作站并重新添加主机。
- 工作站被攻破 = 可拒绝服务、可伪造账号/授权；只把工作站部署在信任的服务器与可信内网。
