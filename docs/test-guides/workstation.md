# 工作站：给产品所有者的代测步骤

> 更新：2026-11-11。

> 全程在公司内网 / VPN，**不要做端口映射或公网暴露**。工作站机器需要 Node ≥ 22；目标电脑只需能访问工作站，不需要 Node。真实模型 Key 不必配置；登录、主机登记与转发不依赖模型（发消息需要至少一个可用账号）。
> 设计见 `docs/workstation.md`；有问题用反馈模式导出 `tandem-feedback-*.json` 发飞书。

## 零、调试版自动登录（只调试版，发布版没有）

**桌面调试版与网页调试版**在**回环地址**（`127.0.0.1` / `localhost`）打开时自动拉起本机工作站并登录「调试账号」（用户名 `debug`），本机主机与一台**演示主机**（演示模型/会话/设备）都在列表里，不用注册。直接打开不带 `?token=` 的 Host 地址（如 `http://127.0.0.1:7878/`）也一样。适合本地调试，不代表正式账号流程。

- 未登录时打开任何页面先看到登录页；调试版回环会自动登录，所以通常直接进主界面。
- 发布版、非回环地址、`TANDEM_DEBUG_ACCOUNT=0`（CLI/e2e 模拟发布语义）都不会自动登录，必须正常注册/登录。

- 侧栏底部账号位置显示「调试账号」和「调试」小标记；账号菜单里有 **退出调试账号**、**用其他账号登录**。
- 退出后本次运行不再自动登录；下次打开也不会自动登录。要恢复：**设置 → 外观 → 调试账号自动登录** 打开开关（打开时若本机工作站可用会立即登录）。
- 想测真实注册流程：在调试版里退出调试账号 → 「用其他账号登录」→ 注册（第一个真实注册用户仍是管理员）；或直接用**发布版**测试。调试账号不算第一个用户，也不是管理员。
- 管理员在 **设置 → 成员与分享 → 账号** 列表能看到 `debug` 账号并带「调试」标记。
- 随机密码保存在 `<TANDEM_HOME>/workstation/debug-account.json`（独立运行 `tandem-host workstation` 时是 `<TANDEM_HOME>/debug-account.json`），权限 0600；不要截图或发群。`POST /api/debug/auto-login` 只在调试版注册，且只接受 `127.0.0.1` / `::1` 来源，局域网其他机器请求会 404。
- 连接**非本机**工作站时不会自动登录；只有对方也是调试版、且你用回环地址（`http://127.0.0.1:<端口>`）打开时，登录页才显示「使用调试账号登录」。
- 只跑 `tandem-host workstation`（调试版）也会自动建好调试账号，但它不跑 agent，所以不会自动添加本机主机；需要时按下面的个人模式显式添加。
- 联调 CLI/浏览器时默认就会自动拉起与登录；设 `TANDEM_DEBUG_ACCOUNT=0` 可模拟发布语义（不自动拉起、不自动登录）。发布版无此开关。

## 一、个人模式（一台机器同时是工作站 + 主机）

1. 正常打开桌面的 Tandem Host（默认 8270）。
2. 侧栏底部 **设置 → 成员与分享 → 工作站** →「连接工作站」。
3. 选 **把这台电脑作为工作站**：本机内嵌启动工作站（默认 `8481`，独立数据目录），页面显示地址。
4. 在工作站页面 **创建工作站**：填工作站名称、管理员用户名（3–32 位）、密码（≥ 8 位）→ 创建。第一个账号就是管理员。
5. 回到工作站页/空状态，点 **添加主机**：弹层给出按平台切换的一行命令（Windows PowerShell / macOS / Linux），令牌一次性、15 分钟有效，显示倒计时；本机也提供 **添加这台电脑** 一键按钮。
6. 先只看登录后的空状态：账号下没有主机时显示「先添加一台主机」，新会话按钮禁用并说明原因；点 **添加这台电脑** 后主机列表出现本机（在线绿点），可以新建会话、发一条消息看到流式回复。
7. 在**另一台机器**上用一行命令添加（Windows 复制 PowerShell 命令，macOS/Linux 复制 curl 命令）：执行完客户端弹层应从「等待主机连接…」变成「已连接 <主机名>」，主机列表出现第二台主机，两台都能切换、建会话。

**本机也要显式添加**：工作站服务自身的 Host 不会自动出现在任何账号的主机列表里；不添加就看不到它，这是预期。

## 二、团队模式（服务器只跑工作站，成员机器作为主机）

服务器（内网 Linux，Node ≥ 22）：

```bash
TANDEM_HOME=/var/lib/tandem-workstation tandem-host workstation --host 0.0.0.0 --port 8481
```

防火墙只允许公司网段访问 8481。也可用 Docker（只发布到内网）：

```bash
docker build -f deploy/workstation/Dockerfile -t tandem-workstation .
docker run -d --name tandem-workstation -p 8481:8481 -v tandem-workstation-data:/data \
  -e TANDEM_HOME=/data tandem-workstation
```

1. **管理员**首次打开 `http://<服务器IP>:8481` → 创建工作站（第一个注册账号是管理员）。
2. **其他成员**打开同一地址 → **注册账号**。默认开放注册；管理员可在「工作站」页改为「仅邀请」，之后用「生成邀请码」发给成员。
3. **每台主机**（包括管理员自己的电脑）：
   - 桌面端：设置 → 成员与分享 → 工作站 → 连接工作站 → 用账号登录工作站；但**登录 ≠ 添加**。
   - 管理员/成员在工作站页 **添加主机** → 复制对应平台的一行命令（安装执行器），在主机那台机器上执行一次（窗口停在「已连接工作站」即正常，主机在前台运行）。加 `--service` / `-Service` 才设置开机自启（下次登录生效）。本机也可以在弹层里点「添加这台电脑」。
4. **可见性**：成员 A 只看到自己添加的主机；成员 B 看不到 A 的主机。A 在「工作站 → 我的主机 → 授权」把某台主机（可限定项目目录）授权给 B，角色选 协作者/审批者/观察者；B 刷新后只看到被授权的主机。
5. **手机/新电脑**：只填工作站地址登录，主机列表自动出现，不需要抄主机地址或主 token。
6. **吊销/离职**：管理员在工作站页禁用账号；该账号的请求立即 401，已开的 WS 被断开；主机端 10 秒内轮询到吊销快照兜底。
7. **只开工作站端口**：在客户端所在机器上确认 `http://<主机IP>:<主机端口>` 不可访问也能正常用；客户端只访问 8481。

## 三、验证「工作站看不到会话内容」

工作站转发的是客户端与主机之间的端到端加密流量（`/_e2e`）。可以：

- 在工作站进程日志里只应看到主机上线/下线；不应出现会话正文、命令或 Key。
- 用浏览器开发者工具看 `/h/<hostId>/_e2e/*`：请求体是密文；工作站转发但不解密。
- 确认工作站页面/接口不提供「查看某台主机会话」的入口；管理员也不能绕过主机权限读别人的会话。

## 四、迁移旧「工作区 / 账号中心」

1. 用旧版本创建过工作区的那台机器，停掉旧 Host，用同一个 `TANDEM_HOME` 启动 `tandem-host workstation`。
2. 打开工作站页面，用原所有者账号登录：角色变为**管理员**；原账号中心 Host 不再作为主机出现（它现在是工作站服务）；原已加入的其他 Host 归到该管理员账号下。
3. 需要继续用本机执行任务时，按「添加主机」重新把本机加进来（预期行为）。
4. 设备令牌、网关令牌仍有效；账号被禁用/授权撤销时联动失效。

## 五、本地模式（不回归）

不连接工作站时，原有「添加主机：地址 + token」完全保留：`http://<主机>:8270/?token=<主token>` 打开，新建/继续会话、审批、设备、看板等应与升级前一致。工作站登录与手工主机可以并存。

## 五之二、在 Windows 上代测远端执行器（用户实机）

### 前置条件（Windows）

- Windows 10/11 的 PowerShell（Windows PowerShell 5.1 或 PowerShell 7 都可）。**不需要 Node.js，不需要管理员。**
- 这台电脑能访问工作站地址（例如 `http://<工作站IP>:8481`）。
- 执行器只出站连接工作站，不监听端口；安装在 `%USERPROFILE%\.tandem-executor`，与桌面版的 `%USERPROFILE%\.tandem` 互不影响。

### A. 浏览器（Chrome / Edge）

1. 打开工作站地址，用账号登录；登录后没有主机时应显示「先添加一台主机」空状态，新会话按钮灰掉并有说明。
2. 点「添加主机」：弹层默认选 Windows，命令形如 `& ([scriptblock]::Create((irm http://<工作站地址>/install.ps1))) -Token 'ach_…'`。令牌旁有 15 分钟倒计时。「开机自启（需要相应权限）」默认关闭，本轮先不勾。
3. 弹层文案应写明目标机器只需能访问工作站、不需要安装 Node.js。

### B. Windows 上执行一行命令（4 步）

1. 在 PowerShell 粘贴执行第 A.2 步复制的命令。
2. 输出应依次显示「正在下载执行器… → 正在校验 sha256… → 正在安装到 …\tandem-exec.exe … → 正在登记本机到 … → 已登记并连接工作站 …，主机 <电脑名>」。窗口停在这一行不退出是正常的（前台运行，关闭窗口即断开）。
3. 回到客户端弹层：应从「等待主机连接…」变成「已连接 <电脑名>」，主机列表出现该电脑。新建会话，让助手「在工作目录写一个 hello.txt 再读回」，应能成功。
4. 关掉 PowerShell 窗口，客户端里该主机应变为离线。再把同一命令执行一次：令牌已用，应提示「绑定码无效、已使用或已过期」并退出（退出码非零）。可选：命令末尾加 `-Service`，执行后 `reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v TandemExec` 能查到启动项。
5. 失败时把窗口里的完整输出回传。常见原因：「无法从 …/executor/windows-amd64 下载」（工作站地址不可达或工作站没有该平台执行器）、「执行器校验失败」（下载内容被改动或不完整）、「绑定码无效、已使用或已过期」（在工作站重新生成后再执行）。

### C. macOS / Linux 上执行一行命令

```bash
curl -fsSL http://<工作站地址>/install.sh | sh -s -- --token ach_…
```

前台运行，关闭终端即断开。加 `--service` 设置开机自启（Linux 写 `systemd --user` 单元，macOS 写 LaunchAgent，下次登录生效；没有 systemd --user 时只提示，不影响连接）。令牌一次性，用过后再执行同一命令应被拒绝。

## 六、需要回传的信息

- 每一步的截图（尤其是：首次创建工作站、添加主机弹层、主机列表在线/离线、授权弹层、用户 B 只看到被授权主机）。
- 哪台机器 / 哪个账号 / 角色；浏览器控制台报错；工作站与主机日志（`TANDEM_HOME` 同目录或桌面端日志）。
- 若主机一直离线：确认主机能访问工作站地址、注册令牌未过期（15 分钟、一次性）、该主机未被其他账号登记（同一 hostId 不能换主人）。

## 七、安全提醒

- 工作站账号密码、绑定码、邀请码不要发到公网群聊或截图。
- `~/.tandem/workstation/accounts.json`（或 `TANDEM_HOME/accounts.json`）含工作站私钥，按敏感配置对待（600 权限）；定期备份，怀疑泄露时重建工作站并重新添加主机。
- 工作站被攻破 = 可伪造账号/授权并拒绝服务；主机内容仍由主机端逐请求验签与 E2E 保护。只把工作站部署在信任的服务器与可信内网。
