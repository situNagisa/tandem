# Tandem 设计原则

> 更新：2026-11-11。只写原则；单点决定落实为 `scripts/decisions-check.mjs`、`scripts/ui-audit.mjs` 与 `e2e/regression.mjs` 的检查，修复记录在提交信息里。用户原话优先；原则或检查与用户新指示冲突时先问用户，不自行推断。

## 1. 气质与色彩

- **P01 温暖、安静、克制。** 大量留白、暖中性灰、细边框与层次背景、微动效，不用重阴影和饱和色。为什么：用户选定 Claude 桌面版的方向。覆盖：所有页面、面板与组件。
- **P02 几乎无彩色。** 层次只靠中性灰明度差；橙色只用于品牌、发送按钮、待审批提示，键盘焦点环用中性灰。为什么：用户多次否决花花绿绿与橙色越界（R04）。覆盖：除代码块、上下文分类、会话图之外的界面。
- **P03 状态用点或文字，不做整块色底。** 在线/空闲/成功不显示或中性灰点，运行中用中性转圈，待审批橙点；错误只用 `--danger` 文字；离线用 `--text-tertiary`。警告统一 `--t-warning`，语义色饱和度与对比度达标。为什么：避免红绿廉价感，同时保证可辨认。覆盖：状态、警告、错误、预算提醒。
- **P04 例外色只限明确区域。** 代码高亮按 GitHub Light/Dark 的饱和度；上下文分类色鲜明协调、同项同色；会话图用泳道色但节点形状统一。为什么：用户要求「颜色鲜明、协调」「会话图可以用彩色，不要各种各样的节点」。覆盖：代码块、上下文卡、会话图、diff 状态字母/增删数字。
- **P05 文字必须够亮、够大。** 正文、消息、列表、按钮、菜单、输入 ≥13px；辅助、时间、标签、设置帮助 ≥12px；只有 kbd 与极小徽标可用 11px，禁止 9/10px；深色次要文字在选中/hover 层仍 ≥4.5:1。为什么：用户多次反馈「灰蒙蒙、字太小、昏沉沉」。覆盖：所有文字与对比度。
- **P06 字体与字重固定。** 正文无衬线、问候用衬线、代码等宽；次要文字不用 300 细体，标题 500–600、按钮 500、正文 400。为什么：层级靠字重与亮度，不靠彩色或极细字。覆盖：全局排版。
- **P07 间距、圆角、阴影、动效用固定档位。** 间距基数 4；控件圆角 6/8/10/12/18–20；阴影 sm/md/lg；微交互 120ms、弹层 160ms、抽屉/对话框 220ms；`prefers-reduced-motion` 关闭位移。为什么：避免逐页手调、尺寸跳变。覆盖：所有布局与动效。

## 2. 布局与结构

- **P08 共享组件优先。** 按钮、输入、下拉、菜单、弹层、卡片、设置行、可拖宽面板只用 `components/ui/*`；禁止手写同类控件、原生 `<select>/<datalist>/input list=`、原生 `title`、自定义滚动条。为什么：同一问题反复在各处复发（R01/R36/R37）。覆盖：所有新 UI 与迁移。
- **P09 菜单与列表紧凑、单行。** 行内只放标题，说明走 tooltip/hint；额外操作放行尾且悬停出现；宽度按内容自适应并设上限，只有实际溢出才截断+全文；带底部操作的菜单主体独立滚动、footer 固定；层级逐级飞出，不出现「返回上一级」。为什么：用户要求单行、紧凑、底部操作常可见。覆盖：所有菜单、列表、级联、命令补全。
- **P10 弹层稳定。** 一律 Portal + 碰撞避让；定位从第一帧稳定，动画/transform 只放内层，触发器按下不缩放；异步内容就绪再打开或用固定尺寸；从一个弹层点另一个触发器不抢焦点。为什么：用户多次反馈「点开抖一下」「tip 被裁」。覆盖：菜单、Popover、Tooltip、下拉、对话框。
- **P11 辅助信息默认隐藏。** 时间、用量、操作按钮、展开箭头等辅助信息默认隐藏，悬停或聚焦出现；触屏没有 hover 时保持可见；行高始终保留，出现时不推挤内容。为什么：用户明确要求「这个文字的显示要移上去才显示」，减少视觉噪音。覆盖：消息时间与用量行、消息操作、卡片标题控件、列表行尾。
- **P12 展开/折叠只改高度。** 宽度只由容器或用户拖拽决定；卡片 `w-full min-w-0`，滚动容器 `scrollbar-gutter: stable`；编辑沿用原宽度；数据到达、展开明细、切换页面都不得改变容器宽度、位置或阅读锚点。为什么：用户反复反馈「点开后宽度改变，一直晃」。覆盖：右栏、Wiki、编辑、懒加载、弹层内容。
- **P13 宽内容不撑开容器。** 代码块、表格、长 diff 的宽度 = 正文阅读列（与段落同左缘、同宽，误差 ≤2px）；超出部分在块内横向滚动并提供可见提示，不得用负外边距向两侧扩张，也不能窄于正文；代码块保留自动换行开关且行号与内容逐行对齐。为什么：用户要求「对齐其他文字的宽度」，整页铺满是严重 bug。覆盖：对话、Wiki、文件预览、diff。
- **P14 交互参考 Claude Code 的行为与信息密度，不照抄外观。** 审批在对话流里、输入框保持可用；错误内联；设置页用阅读宽度；信息密度高但不堆说明。为什么：用户多次说「参考 Claude Code」「照抄行为」。覆盖：审批、错误、设置、搜索、命令面板。
- **P15 入口唯一、层级清晰。** 同一功能只有一个入口；顶栏会话操作 ≤5 个图标，低频收进「⋯ 更多」；侧栏只有一个新会话、一个设置入口；设置按固定分组，合并页只留一个导航入口；所有菜单/设置项可在 Ctrl/Cmd+K 搜到。为什么：用户反复指出重复入口与顶栏太挤（R05）。覆盖：导航、设置、命令面板。
- **P16 一词一概念，文案简洁不口语化。** UI 按术语表用词；按钮即标题，不写操作提示；不用口语化缩写；面向用户的文案集中维护。为什么：用户明确要求术语统一、精简（R31）。覆盖：所有界面文案、提示、错误、无障碍名称。

### 术语表（UI 用词）

| 概念 | 用词 | 不用 |
|---|---|---|
| Host | 主机 | UI 不写 Host 管理 |
| session / subagent | 会话 / 子代理 | 不写「代理」「孙代理」 |
| account / group | 账号 / 分组 | 不写「服务商」作入口 |
| model routing / gateway forwarding | 自动路由 / 模型转发 | 两者不混用 |
| permission mode | 权限模式 | 默认/自动接受编辑/计划/跳过检查 |
| member / share | 成员 / 分享 | 页面写「成员与分享」 |
| board / evaluation / sandbox | 任务看板 / 评测 / 沙箱 | worktree、MCP、Hooks、Secrets、Skills 保留英文 |
| delegation（是否派子代理）/ route bias（执行者用什么模型） | 分工 / 取向 | 委派倾向、执行方式、路由偏好、仅规划 |
| 每轮模式 | 单代理 / 整单交执行者 / 多代理协作 | 低成本 |

## 3. 行为与状态

- **P17 危险或不可逆操作先确认。** 显示影响范围与可撤销入口；危险按钮保持中性，hover 才转 `--danger`，不做红底红框。为什么：用户要求合并、压缩、删除等操作可预期（R11）。覆盖：合并、压缩、删除、回退、密钥变更。
- **P18 长列表/长会话可懒加载，但辅助视图必须能到达。** 大纲、搜索、固定轮、收件箱跳转走同一条「先加载再定位」路径；固定轮不卸载；未加载段有固定高度占位与明确标识，失败要提示。为什么：用户多次遇到「大纲里有、点了没反应」（R40）。覆盖：消息列表、轮次大纲、搜索、会话图。
- **P19 移动端是同一产品的紧凑形态。** <768px 侧栏变抽屉、输入框贴底含安全区、触控目标 ≥44px；轮次大纲改为顶栏胶囊+底部抽屉；不假设悬停。为什么：手机是主要入口之一。覆盖：所有页面在手机/窄屏。
- **P20 只读视图与正常视图同构。** 外部会话、子代理会话、分享页复用消息列表、轮次大纲、信息面板；缺的数据项不渲染，不显示「未知」占位；只读时隐藏输入与固定图钉。为什么：用户要求「预览的外部会话也要跟正常会话一样」（R38）。覆盖：外部会话、子代理、分享、演示。
- **P21 用户定过的行为无新指示不改。** 改动前先查本页与 `decisions-check`；理解超出用户原话、或与既有决定冲突时先问用户；建议不进任务。为什么：用户多次说「我之前说过，但还没改」（R61）。覆盖：所有 UI 与交互改动。
- **P22 进行中要看得见，排队不能丢。** 流式、等首个 token、等工具返回时在消息流末尾显示中性进度与计时；工具行执行中显示 spinner/已运行时长；运行中发送的消息先作为排队气泡原位显示，被 agent 读取后原位替换，不能消失或跑到末尾。为什么：用户要求「运行/输出/工具都要看得出在跑」「排队消息不能消失」。覆盖：消息流、工具行、输入框排队、侧栏运行态。

## 4. 无法自动检查的决定

- 暂不做 iOS，先专注安卓、桌面与网页（2026-11-07）。
- Edge 划词迷你菜单无法由网页关闭：网页端接受浏览器行为，用户可在 Edge 设置→外观关闭；桌面版不受影响（2026-11-09）。
- 「参考 Claude Code」指行为与信息密度，不指像素级外观；具体取舍由评审判断。
- 视觉气质（温暖、安静、克制）只能靠 token 与评审约束，无法逐项断言。
