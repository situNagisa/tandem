# 分工路由 v2（角色分工 + 领域专长）

> 2026-11-08。产品所有者：理解意图、规划、审查要用强模型；跑命令、装依赖、按明确指令改文件用便宜模型；优先性价比高的模型（DeepSeek），领域强项模型（前端 Kimi）按“专长收益 vs 价格”策略使用。本文是 v1 的设计与范围。

## 1. 目标与场景

同一任务内按**角色**切模型，而不是每一轮整体换一个模型：

1. **修前端样式**：Sonnet 读代码定位并写出 3 步计划 → Kimi（前端专长）改组件与样式 → DeepSeek 跑 lint/test → Sonnet 看结果收尾。
2. **装依赖跑构建**：任务简单，直接 DeepSeek 执行；连续失败两次升级 Sonnet 接管，修好后回到 DeepSeek。
3. **纯问答/改名**：不规划、不审查，直接便宜模型一次完成。

原则：强模型只做“必须聪明”的判断，执行默认走最便宜可用的模型；专长模型只在领域匹配且复杂度够高时使用。

## 2. 概念

- **角色**
  - `planner` 规划者：理解意图、只读定位、写清子步骤；复杂任务的第一阶段。
  - `executor` 执行者：跑命令、装依赖、按明确计划改文件；默认最便宜候选。
  - `specialist` 专长执行者：领域匹配（前端/后端/测试…）且复杂度 ≥ 阈值时替代执行者。
  - `reviewer` 审查者：执行结束后检查结果、补最后一刀；默认与规划者同模型，只有够复杂的任务才启用。
- **领域标签** `ui | backend | test | docs | data | ops | general`
  - v1 由规则推断：用户消息关键词 + 最近工具调用的文件扩展名/路径/命令（`package.json`、`.tsx`、`npm test`、`npm install`、`Dockerfile` 等），最近调用权重更高。
  - 规划者可在计划文本中标注领域（后续版本解析并覆盖规则），v1 不依赖模型输出。
- **角色绑定**：每个角色绑定候选池中的一个模型（账号/分组/模型）；未绑定时回落到候选池档位（规划=最强档，执行=快速档）。
- **策略**
  - 复杂度阈值：`planThreshold`（默认 50）以下直接执行；`reviewThreshold`（默认 65）以上才审查。
  - 专长门槛：每个领域映射自带 `minComplexity`（默认 55）；预算压力 ≥ 0.5 时不启用专长模型。
  - 失败升级：同一轮连续 2 次工具失败或输出坏 JSON，下一次请求升级到规划者模型接管；成功后正常回落。
  - 成本上限：`costCapUsdPerTurn`（默认关闭）。本轮累计请求花费触顶后，后续请求一律用最便宜的可用候选，并跳过规划/审查；会话里插入一次提示。
  - 预算紧张：现有 `budgetPressure` 逻辑继续生效，额外禁用专长模型、跳过审查。

## 3. 机制选择：同会话按轮切模型（v1）

| 维度 | 同会话按轮切角色（选） | Task 派发子代理预设 |
|---|---|---|
| 上下文 | 共享完整对话：规划者读过的文件、计划、执行结果都在同一上下文，执行模型无需重新发现 | 子代理上下文独立，需要把计划与关键上下文塞进 prompt，重复读文件 |
| 成本 | 每次模型请求按角色计价；只多出规划/审查的少量输出，输入不重复 | 规划上下文 + 执行上下文双份输入，子代理启动开销大 |
| 可解释性 | 每次请求都有角色/领域/理由，提示行与按角色用量天然对齐 | 子会话里能看到，但主会话只看到 Task 结果摘要，角色切换不直观 |
| 确定性 | 服务端状态机决定角色，不依赖模型是否愿意调用 Task | 依赖模型主动调用 Task，delegation=less 时不稳定 |
| 隔离/并行 | 同一工作区，顺序执行 | 天然并行、可隔离 worktree |

**结论**：v1 用同会话按轮切模型，把角色做成 agent 循环里的阶段状态机：`plan → execute → review`。
Task 子代理机制保留，用于用户显式并行/隔离；后续版本允许规划者在计划中把独立子任务派给“执行者预设”，二者组合，不另起路由系统。
实现上扩展 `model-routing.ts` 与 `routing-settings.ts`，候选池、价格、可用性、升级/回落、预算逻辑全部复用。

### 状态机（单轮）

```
turn start
  ├─ complexity < planThreshold 或预算触顶 → execute（direct）
  └─ plan（规划者，只读工具）──无工具调用/最多 2 次──> execute
execute（执行者/专长执行者，全工具）
  ├─ 连续失败 2 次 → planner 接管（升级）
  └─ 无工具调用
       ├─ complexity ≥ reviewThreshold 且未触顶 → review（审查者）
       └─ 结束
review（审查者，全工具）→ 结束；若继续调用工具则留在 review
```

每次请求前重新推断领域，因此“改 .tsx 用 Kimi、跑 npm test 用 DeepSeek”可在同一轮内发生；切换模型时插入一行提示。

## 4. 协议与数据

- 会话：`SessionSummary.routeMode?: 'auto' | 'division'`；`autoRoute` 仍为 true（兼容旧客户端），模型菜单“自动 / 分工”两个入口。
- 设置：`ModelRoutingSettings.division?: DivisionRoutingSettings`
  - `planner? / executor? / reviewer?: RouteAssignment`（profileId/groupId/model）
  - `domains: DomainRoute[]`：`{ domain, profileId?, groupId?, model, minComplexity, note? }`，`note` 为“前端强项”等专长说明
  - `planThreshold`、`reviewThreshold`、`costCapUsdPerTurn`
- 决策：`ModelRouteDecision` 增加可选 `role`、`domain`、`specialist`、`costCapped`；`reason` 仍是人话。
- 用量：`UsageStatsRow` 增加可选 `role`、`routeSavedUsd`；会话 `AutoRouteSavings.byRole` 记录每个角色的调用数与花费，用于“节省”归因。
- 提示行：`分工 · 规划 Sonnet（复杂度 72）`、`分工 · 执行（前端）Kimi（专长匹配）`、`分工 · 审查 Sonnet（收到执行结果）`；hover 展示分数/领域/阈值/价格。

## 5. 界面

1. **模型菜单**：在“自动”下新增“分工”项，副标题显示当前角色绑定摘要；选中后会话进入分工模式。
2. **设置 → 模型路由**：保留候选池与偏好，新增“分工”区：
   - 三个角色绑定下拉（账号 › 分组 › 模型，显示单价）；
   - 领域映射表：领域、模型、专长说明、最低复杂度、单价；
   - 策略：规划阈值、审查阈值、每轮成本上限、预算紧张时禁用专长（开关）；
   - 三套预设一键填充（见下）。
3. **会话提示行**：每次角色/模型变化显示一行灰字，可展开理由（复用现有 route notice）。
4. **用量页**：新增“按角色”表（调用、token、花费、对比强力档节省）；右栏会话用量卡显示角色花费拆分与节省。

## 6. 开箱预设

预设只用当前已配置账号里真实存在的模型；找不到对应模型时留空并提示“未找到，请手动选择”。

- **省钱优先**：规划/审查 = 价格最高的强力档（用户认定的强模型）；执行 = 价格最低的候选（优先 DeepSeek/Haiku/mini/flash）；审查阈值 75；专长仅前端且复杂度 ≥ 65。
- **质量优先**：规划/审查 = 最强档；执行 = 均衡档；审查阈值 45；专长门槛 45。
- **前端专项**：在“省钱优先”基础上把 `ui` 映射到名称含 kimi/moonshot 的前端强项模型（minComplexity 55），其余同省钱优先；找不到时不启用该映射。

预设不写死供应商，按候选池价格与名称关键字推断；所有绑定均可在设置里改。

## 7. v1 范围

**做**：协议字段；设置归一化与持久化；角色状态机（规划/执行/专长/审查、失败升级、成本上限、预算降级）；规则领域推断；模型菜单“分工”；路由设置页角色绑定、领域映射与预设；提示行；会话与全局按角色用量；单测 + mock provider 回归 + Playwright 截图。

**不做（以后）**：规划者输出结构化子任务并自动 Task 派发；领域由模型标注；跨会话/跨任务预算；按任务（多轮）成本上限；专长模型并行 fan-out；学习型价格/质量反馈。以上均可在现有字段上增量扩展，不破坏 v1。
