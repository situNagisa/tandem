# 模型路由：分工与取向

> 更新：2026-11-10。**主会话模型恒定，执行交给 Task 子代理**：prompt 缓存按模型/服务商命中，来回换模型会让整段上下文按未命中价重发。按难度自动选主会话模型另见 `architecture.md` 的 `model-routing.ts` 与设置「模型路由」。

## 两个维度

| 维度 | 取值 | 含义 |
|---|---|---|
| 分工 `delegation` | 关闭 / 适度（默认） / 积极 | 派不派子代理。关闭：不提供 Task；适度：只派明显独立的多步任务；积极：尽量拆分并行 |
| 取向 `routeBias` | 省钱 / 均衡（默认） / 质量优先 | 执行者与子代理用什么模型；省钱时机械任务整单交执行者。缺省跟随设置「模型路由 → 取向默认」 |

「仅规划」已移除：它会把主会话工具集换成规划类，与计划模式（权限模式 `plan`，`ExitPlanMode`）是同一类事，由权限模式承担。

## 每轮的解释模式

规则分类（不调用模型）给每条消息定一种模式，并在提示行写出「模式 · 模型 · 理由」：

| 分工 \ 取向 | 省钱 | 均衡 | 质量优先 |
|---|---|---|---|
| 关闭 | 单代理 | 单代理 | 单代理 |
| 适度 | 机械任务整单交执行者；明显独立的多步任务多代理协作 | 明显独立的多步任务多代理协作 | 同均衡，子代理用强力档 |
| 积极 | 机械任务整单交执行者；行动类任务尽量拆分 | 行动类任务尽量拆分，多代理协作 | 同均衡，子代理用强力档 |

- 单代理：主会话自己完成，不提供 Task。整单交执行者：主会话不请求模型，整条消息交给执行者子代理，摘要回主会话。多代理协作：规划者只读定位后用 Task 派自包含子任务，摘要回规划者。
- 分工关闭：不规划、不出提示行。「直接做 / 不要派」、问答解释、需要大量上下文判断的任务（除非多步机械）：单代理。预算偏紧或没有可用的执行模型：单代理。
- 整单交执行者：省钱、机械动作（装依赖、跑命令、机械改写）、非问答、复杂度 < 50、不超过 240 字、不是多步机械。
- 多代理协作：适度要求机械动作 ≥ 2 且多步，或领域专长匹配且复杂度 ≥ 门槛，或复杂度 ≥ 90 且多步；积极要求非问答且有行动/机械/多步特征，复杂度 ≥ 35。
- 学到的偏好：同类任务在分工前确认卡里两次改为「单代理」后，同类默认单代理。

**不分工硬清单**：纯对话与问答；需大量上下文判断的修改；小改动；用户说「你直接做/不要派子代理」；分工关闭。

**失败升级**：整单交执行者失败 → 本轮主模型直接处理并提示；多代理执行者连续失败 2 次 → 规划者接管，禁止无限重试。

## 执行者与子代理的模型

- 设置里为执行者或领域绑定的模型优先。
- 未绑定时按取向选档：省钱 → 快速档，均衡 → 均衡档，质量优先 → 强力档；同档内省钱与均衡取最便宜，质量优先取最贵；档位缺失时就近取。
- 规划者（主会话）保持会话模型，不随取向变化。

## 机制

- **Task 只在多代理协作的回合开放**；单代理与整单交执行者的回合不提供 Task，分工关闭时全程不提供。分工的系统提示段只在提供 Task 的回合注入。
- 子代理（嵌套层级 > 0）不经过规则分类，按会话分工决定是否可再派。
- 每轮成本上限（`costCapUsdPerTurn`）只对「积极」生效；「适度」不设上限。
- 分工前确认（`confirm`）：计划卡可换模型、删子任务、改为单代理或整单交执行者后再派发。
- 用量按角色统计，节省对比「全程使用最强候选」，不变。

## 数据与协议

- 会话：`delegation?: 'more' | 'less' | 'none'`（缺省按 Host 设置，默认 `less`）、`routeBias?: 'cost' | 'balanced' | 'quality'`（缺省跟随全局取向）。
- 发送消息：`{ type: 'send', route?: TurnRouteOverride }`。一次性覆盖只作用于这一条；排队消息不带覆盖。勾选「记住为会话偏好」时两个维度都写入会话。
- 旧数据迁移（读取时一次、幂等、写回）：`routePreference: direct` → 分工关闭；`division` → 分工积极；`cheap` → 取向省钱（分工为关闭或未设时改为适度）；`auto`、未设、`routeMode` → 不变；`delegation: orchestrate` → 积极。
- `TurnRouteMode`（`direct | cheap | division`）只表示每轮的解释模式。

## 界面

1. 输入框底栏唯一的「分工与取向」菜单：两个子菜单各一组单选，下方「记住为会话偏好」。沿用现有 Menu 组件。
2. 提示行只展示结论，不提供覆盖按钮；要改这一轮，用输入框菜单。
3. 提示行透明（反馈1323#03）：本轮有路由注入时，提示行可展开看实际注入的文本原文（分工系统提示 + 「多代理协作 · 本轮」，或整单交执行者时执行者收到的任务说明）；单代理直接回合不注入，悬停说明「仅用于选择分工与模型，未向模型注入内容」。字段 `RoutePlan.injected` 由服务端在计划时写入。
4. 新建会话对话框里选的分工与取向，创建时写入会话。
5. 设置 →「模型路由」：取向默认、角色绑定、领域映射、分工阈值、成本上限、分工前确认、学到的偏好。

## 价格与倍率

内置官方参考价（Claude、GPT-4o/4.1/5/6、o 系列、DeepSeek、Gemini、Kimi/Moonshot、Qwen、GLM，按前缀匹配，表头注明参考日期）。实际价 = 官方价 × 账号倍率 × 分组倍率；账号按模型覆盖单价优先，覆盖价不乘倍率。计费、压缩、网关、Wiki、评测与菜单展示共用 `resolvePriceForModel` / `priceForModel`；菜单 tooltip 显示计算式，无参考价显示「无参考价 · 去设置」；历史花费不重算。

## 思考强度

`packages/server/src/providers/capabilities.ts` 是唯一能力表：按模型 id 推断档位、厂商叫法与参数映射；provider 返回能力优先，账号/分组可覆盖。OpenAI 走 `reasoning_effort`（o 系列 low/medium/high，gpt-5/6 含 minimal）；Anthropic 走 `budget_tokens`（2K/8K/16K/32K）；Grok/Gemini/DeepSeek 按各自 API；不支持思考返回空数组，菜单隐藏该项。芯片只显示模型名，强度只在菜单/tooltip/aria-label。
