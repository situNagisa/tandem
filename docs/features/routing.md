# 模型路由：分工与取向

> 更新：2026-11-18。**主会话模型恒定，执行交给 Task 子代理**：prompt 缓存按模型/服务商命中，来回换模型会让整段上下文按未命中价重发。按难度自动选主会话模型另见 `architecture.md` 的 `model-routing.ts` 与设置「模型路由」。

## 三个维度

| 维度 | 取值 | 含义 |
|---|---|---|
| 分工 `delegation` | 关闭 / 适度（默认） / 积极 | 派不派子代理。关闭：不提供 Task；适度：只派明显独立的多步任务；积极：尽量拆分并行 |
| 取向 `routeBias` | 关闭 / 省钱 / 均衡（默认） / 质量优先 | 执行者与子代理用什么模型；关闭：不注入取向说明（分工照常，执行者按均衡档）。缺省跟随设置「模型路由 → 取向默认」。「原生」开关已删除（反馈1724#02），旧 `routeNative=true` 读取时迁移为取向关闭、分工保持原值，旧设置 `native` 迁移为「取向默认 = 关闭」。

「仅规划」已移除：它会把主会话工具集换成规划类，与计划模式（权限模式 `plan`，`ExitPlanMode`）是同一类事，由权限模式承担。

## 每轮的解释模式

规则分类（不调用模型）给每条消息定一种模式，并在提示行写出「模式 · 模型 · 理由」：

| 分工 \ 取向 | 省钱 | 均衡 | 质量优先 |
|---|---|---|---|
| 关闭 | 单代理 | 单代理 | 单代理 |
| 适度 | 机械任务整单交执行者；明显独立的多步任务多代理协作 | 明显独立的多步任务多代理协作 | 同均衡，子代理用强力档 |
| 积极 | 机械任务整单交执行者；行动类任务尽量拆分 | 行动类任务尽量拆分，多代理协作 | 同均衡，子代理用强力档 |

- 单代理：主会话自己完成，不提供 Task。整单交执行者：主会话不请求模型，整条消息交给执行者子代理，摘要回主会话。多代理协作：规划者只读定位后用 Task 派自包含子任务，摘要回规划者。
- 分工关闭：不规划、不出提示行。「直接做 / 不要派」、问答解释、需要大量上下文判断的任务（除非多步机械）：单代理。预算偏紧或没有可用的执行模型：单代理。
- 取向关闭：规则分类与分工照常，只是不注入「取向 · 本轮」段；执行者/专长档位按均衡处理。
- 整单交执行者：省钱、机械动作（装依赖、跑命令、机械改写）、非问答、复杂度 < 50、不超过 240 字、不是多步机械。
- 多代理协作：适度要求机械动作 ≥ 2 且多步，或领域专长匹配且复杂度 ≥ 门槛，或复杂度 ≥ 90 且多步；积极要求非问答且有行动/机械/多步特征，复杂度 ≥ 35。
- 学到的偏好：同类任务在分工前确认卡里两次改为「单代理」后，同类默认单代理。

**不分工硬清单**：纯对话与问答；需大量上下文判断的修改；小改动；用户说「你直接做/不要派子代理」；分工关闭。

**失败升级**：整单交执行者失败 → 本轮主模型直接处理并提示；多代理执行者连续失败 2 次 → 规划者接管，禁止无限重试。

## 执行者与子代理的模型

- 设置里为执行者或领域绑定的模型优先。
- 未绑定时按取向选档：省钱 → 快速档，均衡 → 均衡档，质量优先 → 强力档；同档内省钱与均衡取最便宜，质量优先取最贵；档位缺失时就近取。
- 规划者（主会话）保持会话模型，不随取向变化。

## 机制

- **Task 只在多代理协作回合开放**；单代理与整单交执行者的回合不提供 Task，分工关闭时全程不提供。分工的系统提示段只在提供 Task 的回合注入；取向段（执行者/专长模型）在取向非「关闭」时才注入，两段分开、互不牵连。
- 子代理（嵌套层级 > 0）不经过规则分类，按会话分工决定是否可再派。
- 每轮成本上限（`costCapUsdPerTurn`）只对「积极」生效；「适度」不设上限。
- 分工前确认（`confirm`）：计划卡可换模型、删子任务、改为单代理或整单交执行者后再派发。
- 用量按角色统计，节省对比「全程使用最强候选」，不变。

## 数据与协议

- 会话：`delegation?: 'more' | 'less' | 'none'`（缺省按 Host 设置，默认 `less`）、`routeBias?: 'off' | 'cost' | 'balanced' | 'quality'`（缺省跟随全局取向）。`RoutePlan.bias` 记录本轮取向，`injected` 里没有「取向 · 本轮」即表示取向关闭。
- 新建会话：未传 `routeBias` 时跟随设置「模型路由 → 取向默认」。修改会话：`PATCH /api/sessions/:id` 的 `routeBias`。
- 发送消息：输入框里的选择已直接写入会话，不再附带一次性覆盖；`TurnRouteOverride` 只供确认卡「改为单代理」等内部路径使用。
- 旧数据迁移（读取时一次、幂等、写回）：`routeNative: true` → 取向关闭（分工保持原值，字段删除）；`routePreference: direct` → 分工关闭；`division` → 分工积极；`cheap` → 取向省钱（分工为关闭或未设时改为适度）；`auto`、未设、`routeMode` → 不变；`delegation: orchestrate` → 积极。
- `TurnRouteMode`（`direct | cheap | division | native`）只表示每轮的解释模式。

## 界面

1. 模型菜单（输入框底栏模型芯片点开）底部分组：「分工」（关闭 / 适度 / 积极）与「取向」（关闭 / 省钱 / 均衡 / 质量优先）各一组单选，两者是一组，其下一条分隔线与「思考强度」及之后的账号设置分开。选择立即写入当前会话，后续消息都用这组设置，没有「记住为会话偏好」。模型芯片只显示模型名，不额外显示分工文字。沿用现有 Menu 组件。
2. 提示行只展示结论，不提供覆盖按钮；要改这一轮，用模型菜单。
3. 提示行透明（反馈1323#03）：本轮有路由注入时，提示行可展开看实际注入的文本原文（分工系统提示 + 「多代理协作 · 本轮」+ 取向非关闭时的「取向 · 本轮」，或整单交执行者时执行者收到的任务说明）；单代理直接回合不注入，悬停说明「仅用于选择分工与模型，未向模型注入内容」。旧版本留下的 `mode: 'native'` 提示行仍按「原生（未注入）」展示，仅用于历史数据。字段 `RoutePlan.injected` 由服务端在计划时写入。
4. 新建会话对话框里选的分工与取向，创建时写入会话；未选时按设置里的「取向默认」。
5. 设置 →「模型路由」：取向默认（含关闭）、角色绑定、领域映射、分工阈值、成本上限、分工前确认、学到的偏好。

## 价格与倍率

价格只有两个来源：官方价格表，或分组里为某个模型设置的自定义单价（账号级自定义单价作为分组未设时的兜底）。官方价格表由 `packages/server/src/model-prices.ts` 唯一实现，数据存在工作站数据目录的 `model-prices.json`（首启用内置表初始化）；设置 →「模型价格」按厂商列出四种单价、分段价、来源链接与更新时间。官方价按模型名前缀取最长命中，**不在型号之间借价或按家族估算**；没列出的型号视为未知单价，菜单与用量卡显示「未知单价 / 该型号尚未收录官方价」，并复用「单价未设置 → 跳到该账号单价覆盖」入口。
- 每条官方价含输入、输出、缓存读、缓存写 5m / 1h 单价；计费按未命中输入、输出、`cache_read`、`cache_creation`（5m/1h 拆分，只给总数时按 5m）分别乘价（Haiku 5.5 提示 token 超过 100K 切高价档）。实际价 = 官方价 × 分组倍率（倍率只属于分组，缺省 1）；自定义单价不乘倍率。界面只展示官方价与倍率，不展示乘出来的单价。历史花费按记账时单价保存，调价不改历史（MODEL-7）。
- 每个厂商的定价页地址与解析规则可在「模型价格」页配置（JSON `models` 数组，或 `{ "type": "html-table", "table": "<选择器>", "columns": {…} }`）；「刷新」由工作站进程抓取定价页，先给差异预览，确认后写入；失败如实显示原因并保留旧价。

## 思考强度

`packages/server/src/providers/capabilities.ts` 是唯一能力表：按「型号 × 实际请求协议」推断档位、厂商叫法与参数映射；provider 返回能力优先，账号/分组可覆盖。同一张表也给出上下文窗口与 1M 开关能力（原生 1M / 4.6 需 beta / 4.5 仅 200K），见 `model-accounts.md`「长上下文（1M）开关」。Anthropic adaptive 型号（4.7 及以后，Sonnet 4.6 无 xhigh）发 `thinking: { type: "adaptive", display: "summarized" }` + `output_config.effort`，档位 low/medium/high/xhigh/max、标签「低 · low … 超高 · xhigh / 最高 · max」、无 token 预算；`display: "summarized"` 必须显式传（默认 omitted 时思考文本为空，UI 看不到「思考了 Ns」）；只有支持 `thinking: { type: "disabled" }` 的型号才有「关」，Opus 5.5 / Sonnet 5.5 / Fable/Mythos 5.x 不能关闭。
manual 型号（4.6 及以前）走 `budget_tokens`，保留 2K/8K/16K/32K 标签。OpenAI 兼容协议访问 Claude 只能走 `reasoning_effort`（low/medium/high），菜单注明「经 OpenAI 兼容协议，由中转决定是否生效」。未显式选择时按官方默认（Opus 5.5 / Haiku 5.5 → medium，其余 → high）显示「默认（高）」且不发送 effort；其余 provider 按各自 API，不支持思考返回空数组、菜单隐藏该项。芯片只显示模型名，强度只在菜单/tooltip/aria-label。

## 验证与限制

- 单测：`model-routing.test.ts`（矩阵、取向档位、学到的偏好）、`session-route-migration.test.ts`（迁移）；回归：`e2e/regression.mjs`「分工路由」用例（取向关闭不注入取向段但分工照常且有 Task、分工关闭零派发、取向省钱整单交执行者、分工积极、确认卡、成本上限、学到的偏好）与模型菜单用例。
- 未做：第三个维度「验证策略」（用户提出，另做）；结构化子任务自动并行 fan-out；跨任务预算；执行者自动验收。
