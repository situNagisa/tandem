# 模型路由：自动路由 + 分工路由 v2

> 更新：2026-11-09。
>
> **已废弃：同一会话按轮切换模型**（2026-11-08 用户否决）。prompt 缓存按模型/服务商分别命中，来回换模型会让整段上下文按未命中价重发，强模型缓存也会失效（成本对比见 §4）。现行做法是**规划者永远是主会话模型、不换模型，执行交给 Task 子代理**，即本文的“分工路由”。按难度自动选模型（自动路由）另见 `architecture.md` 的 `model-routing.ts` 与设置「模型路由」页。

## 1. 目标

- 理解意图、规划、拆分、审查结论交给主会话的强模型；跑命令、装依赖、按明确指令改文件交给便宜执行者。
- 便宜优先（DeepSeek 等）；领域强项模型（如前端 Kimi）只在“领域匹配 + 复杂度够高”时用，贵要有理由。
- **简单任务不能变复杂**：默认直接做；只有满足明确条件才分工。一眼机械的任务整单交给便宜模型，主会话只看结果。

## 2. 三种模式

| 模式 | 谁执行 | 何时 |
|---|---|---|
| **直接做**（默认） | 主会话模型自己完成，零额外请求、零派发 | 对话、问答、解释代码、小改动、需要大量上下文判断的修改、调试分析、架构/评审 |
| **便宜直做** | 主会话不调用；用户消息直接交给便宜执行者子代理，结果摘要回到主会话 | 一眼机械且自包含：跑某条命令、装依赖、格式化、跑 lint/test、重命名、生成样板 |
| **分工** | 主会话（规划者）先只读定位并拆解，用 Task 把自包含子任务派给执行者/专长执行者；结果摘要回到规划者判断与收尾 | 预计多步且存在可独立执行的机械子任务：批量改文件、装依赖并跑构建、生成测试、跑大量命令；或领域专长匹配且复杂度 ≥ 门槛 |

分类由**规则**完成（关键词、长度、领域、预算、历史失败），不额外调用模型；分类结果是一行提示，用户可覆盖。

### 什么时候不分工（硬清单）

- 纯对话 / 问答 / 解释 / 讨论 / 方案比较；用户只想知道“为什么”。
- 需要阅读大量上下文才能判断的修改（跨模块重构、竞态、架构迁移、复杂 bug 定位）。
- 小改动：改一个名字、一个文案、一处样式、单个文件的小编辑。
- 用户明确说“你直接做 / 不要派子代理 / 先别动代码”。
- 当前委派策略为 `none`，或执行者/专长预设不可用、预算已阻止。
- 预计收益（省下的输入 token × 价差）小于子代理启动与摘要开销。

以上情况即使 `routeMode=division` 也走直接做；用户覆盖优先级最高，其次会话偏好，最后规则。覆盖只影响当前消息，可一键记住为会话偏好。

### 失败升级

便宜直做失败（子代理报错/退出）→ 本轮改由主模型直接处理，并插入提示。
分工中执行者连续失败 2 次 → 规划者收到错误摘要后自己接管或换专长模型；禁止无限重试同一子任务。

## 3. 机制：Task 子代理

- 主会话模型 = 规划者（用户当前会话模型），上下文与缓存只属于它，**不切换**。
- 执行用现有 `Task` 机制，新增内置角色 `role=executor|specialist`（可带 `domain`）；服务端从分工设置解析到账号/分组/模型，创建子会话。
- 子代理只收到：任务描述、必要文件路径、验收命令、约束；**不继承主会话历史**。子代理可使用全套工具，完成后只回传最后一段摘要。
- 规划者收到摘要后判断：继续派发、自己补查、或收尾。主会话只保留摘要，不把大量命令输出塞进强模型上下文。
- 规划者的派发指令由系统提示注入（仅分工模式、仅本轮）：
  - 先用只读工具定位，写 2–5 步计划；
  - 每个 Task prompt 必须自包含，不粘贴整段对话；
  - 一两步就能完成的修改自己做，不许为了分工而分工；
  - 前端 UI 领域可派给 `specialist`，其余机械步骤派给 `executor`。
- 领域标签 `ui|backend|test|docs|data|ops|general` 由规则推断（消息关键词 + 最近文件/命令），领域→模型映射在设置里维护，带“专长”说明和最低复杂度。

## 4. 成本账（为什么不再同会话切模型）

设主会话上下文为 `C` 输入 token，强模型价 `P`、便宜模型价 `p`（每 token），缓存读价按 Anthropic 0.1×/OpenAI 0.5×。

- **同会话切模型**：规划 `C·P`，执行时整段 `C` 对便宜模型是首次请求（缓存未命中）`C·p`；再切回强模型，强模型缓存因中间插入其他模型而失效，又付 `C·P`。一轮 ≈ `2C·P + C·p`。
- **子代理分工**：规划 `C·P`（缓存热；后续轮 `C·P·cache`），执行子代理上下文只有 `c << C`（任务描述+必要文件）`c·p`，回到规划者仍是热缓存 `C·P·cache`。一轮 ≈ `C·P + c·p + C·P·cache`。
- 以 `C=100k`、`c=10k`、`P=$3/M`、`p=$0.3/M`、缓存命中 90% 估算：切换方案 ≈ `$0.63`；子代理 ≈ `$0.333`，约省 47%。上下文越大、执行步骤越多，差距越大；子代理还要付一次摘要输出（约 1–3k token），已计入。
- 因此：主会话模型恒定，缓存始终热；执行上下文小；代价是子代理需要自包含说明、可能重复读少量文件。规则只在机械子任务足够大时分工，避免启动开销吃掉收益。

## 5. 数据与协议

- 会话：`routeMode?: 'auto' | 'division'`（兼容现有 `autoRoute`）；`routePreference?: 'auto' | 'direct' | 'cheap' | 'division'`（会话偏好）。
- `ModelRoutingSettings.division`：`planner/executor/reviewer` 绑定、`domains[]`（模型+最低复杂度+专长说明）、`planThreshold`（进入分工的最低复杂度，默认 55）、`costCapUsdPerTurn`（达到后停止继续派发，缺省关闭）。
- `Message.routePlan`：本轮模式、理由、领域、执行者/专长模型，前端渲染提示行与覆盖按钮。
- `ModelRouteDecision`：`role/domain/specialist`；`AutoRouteSavings.byRole` 与 `UsageStatsRow.role/routeSavedUsd` 用于按角色统计。
- Task 输入新增 `role`、`domain`；`ToolContext.runSubagent` 透传。

## 6. 界面

1. **模型菜单**：“自动”旁新增“分工”；选中后会话 `routeMode=division`，模型本身不变。
2. **每个任务一行提示**：`直接做 · 问答/小改动`、`便宜直做 · 装依赖`、`分工 · 前端专长（复杂度 68）`；右侧三个覆盖按钮“直接做 / 便宜直做 / 分工”，点击即记住为会话偏好；Composer 的路由胶囊可对**下一条消息**做一次性覆盖。
3. **设置 → 模型路由**：新增分工区：三个角色绑定（账号›分组›模型，显示单价）、领域映射表（领域、模型、专长说明、最低复杂度、单价）、策略（分工阈值、每轮成本上限、预算紧张时禁用专长）、三套预设。
4. **用量**：按角色统计调用/花费/节省；右栏会话用量显示角色拆分；会话提示行 hover 展示分类理由与预算状态。

### 人工选择与确认

- **发送前**：输入框底栏「执行方式」控件：自动 / 直接做 / 便宜直做 / 分工，默认自动；可勾选「本会话保持」写入会话偏好。手动选择优先于规则，本次消息立即生效。
- **分工前确认**：设置项「分工前确认」：从不 / 仅当预计花费 > $X 或要用贵专长模型 / 总是（默认仅贵时）。需要确认时，消息流出现紧凑计划卡：子任务、模型、预计花费；可逐个换模型、删除子任务，或整单改为直接做/便宜直做；确认后才派发。计划卡同时写入收件箱，手机上打开会话即可处理。
- **运行中可改**：右栏子代理卡片提供「换模型重跑」（选择账号内任意模型）与「改由主会话直接做」（把原始任务交回主会话，按直接做执行）。
- **学习偏好**：每次人工覆盖按「领域 + 机械动作」累计；同类任务 ≥2 次选择同一模式后默认采用（当前只自动采纳“直接做”，其余仍需人工确认）。设置页展示学到的偏好并可清空。

## 7. 预设

只用当前账号里真实存在的模型；找不到就留空并提示手动选择。

- **省钱优先**：规划/审查 = 最强档；执行 = 最便宜（优先 DeepSeek/Haiku/mini/flash）；前端专长门槛 70；分工阈值 55。
- **质量优先**：执行 = 均衡档；专长门槛 45；分工阈值 40。
- **前端专项**：省钱优先 + `ui` 映射到名称含 kimi/moonshot 的模型（门槛 55），找不到则不启用该映射。

## 8. v1 范围与验证

**做**：协议、规则分类（零模型调用）、Task 角色派发与自包含提示、便宜直做与失败升级、主会话不换模型、提示行与覆盖、设置页角色/领域/预设、按角色用量、预算与成本上限粗粒度保护、单测 + mock provider 回归 + Playwright。

**验证**：一组简单任务（问答、改名、解释代码）全部“直接做”且额外请求数为 0；手动直接做零派发；前端任务走分工且专长模型被调用；装依赖走便宜直做；失败升级；确认卡改模型/删子任务后按修改执行并进入收件箱；成本上限阻止继续派发；学习偏好在同类任务上生效；mock 模拟缓存计费，验证主模型缓存命中率与花费。

**以后**：规划者输出结构化子任务并自动并行 fan-out、跨任务预算、执行者结果自动验收、按价格/质量学习路由。

## 9. 价格与倍率（反馈6#04）

- **官方参考价**：`packages/server/src/usage.ts` 内置常见模型单价（每百万 token 美元，按模型名前缀匹配；表头注明「参考官方定价，2026-11」）。新增模型只需补一行前缀；无参考价的模型仍然统计 token，但成本的 0 只在用户设置覆盖单价后通过。
- **倍率**：账号 `multiplier`（默认 1.0）与分组 `multiplier`（默认 1.0，在账号倍率之上叠加）。实际价 = 官方价 × 账号倍率 × 分组倍率。
- **覆盖单价**：账号 `price` 按模型精确/前缀覆盖（高级选项）；命中覆盖时直接使用覆盖价，不再乘倍率。
- **统一入口**：计费（agent 循环、压缩、网关、Wiki、评测）与菜单展示共用 `resolvePriceForModel` / `priceForModel`，避免两处口径不一致。
- **展示**：模型菜单 tooltip 给出计算式（「官方 $3/M × 账号 0.5 × 分组 0.8 = $1.2/M」）与输出/缓存最终价；无参考价显示「无参考价 · 去设置」。用量页说明倍率只影响之后的请求，历史花费不重算。
- **验证**：`packages/server/test/pricing.test.ts` 覆盖倍率叠加、覆盖优先、未知模型、`effectiveProfile` 分组倍率；回归「账号/分组倍率」检查模型菜单计算式。


## 10. 模型菜单与思考强度（反馈7#04 #05）

- **逐级飞出**：主菜单「切换账号 ›」→ 右侧账号列表 → 悬停账号向右弹出分组 → 悬停分组向右弹出模型；点模型即选中并关闭菜单。没有「返回上一级」行，也不在同一面板里替换内容；只有一个账号或一个分组时跳过该级。键盘 → / ← 逐级进入/返回。设置 → 自动路由的「添加候选模型」复用同一个 `ui/ModelCascade`（多选 checkbox 版本）。
- **最近使用模型**：主菜单顶部按使用次数 + 最近时间排序展示最多 6 个模型，可跨账号分组，行内显示「模型名 · 分组」；其余模型通过级联入口查找。没有记录时回退到当前分组的模型。记录存在 `localStorage`（`tandem.recentModels.v1`），发送消息时累加。
- **思考强度由模型决定**：`packages/server/src/providers/capabilities.ts` 是唯一能力表——按模型 id 推断档位、厂商叫法与请求参数映射；provider 模型列表返回的能力优先，账号/分组 `modelCapabilities` 可覆盖。OpenAI 推理模型走 `reasoning_effort`（o 系列 low/medium/high，gpt-5/6 含 minimal/low/medium/high）；Anthropic extended thinking 走 `budget_tokens` 预设（2K/8K/16K/32K）；Grok 按其 low/high 等档位；Gemini / DeepSeek 按各自 API；不支持思考的模型返回空数组，菜单隐藏「思考强度」。
- **验证**：`packages/server/test/capabilities.test.ts` 覆盖档位与请求参数；回归：逐级悬停飞出、点选后菜单关闭且模型落库、顶部最近使用模型、o3 显示厂商档位、未知模型隐藏思考强度。
