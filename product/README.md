# Tandem 产品定义

> 状态：草稿，待产品所有者确认。这是"我们在做什么"的唯一来源：规格与代码不一致时以这里为准。代码、测试、实现文档都从这里派生。

## 产品是什么
Tandem 是一个**工作站服务**：跑在一台服务器上；用户用客户端（桌面、浏览器、手机）连接它；它连接各台**主机**，agent 在主机上执行。会话、账号、模型调用都在工作站；主机只负责执行命令与读写文件。

## 核心概念（全产品只用这些词）
| 词 | 含义 |
|---|---|
| 工作站 | 服务本身。账号、会话、模型账号都存在这里。 |
| 主机 | 执行 agent 的机器。运行工作站的机器自己也是一台主机。远程机器跑一个执行器连上工作站。 |
| 设备 | 接在主机上的外设（ADB、串口……），是开放的种类，不写死。 |
| 会话 | 一次与 agent 的对话，属于一台主机上的一个目录。 |
| 轮 | 一条用户消息加上它引出的全部回复与工具调用。 |
| 会话树 | 一个根会话 + 它的全部分叉（递归）+ 这些会话派出的全部子代理。 |
| 分叉 | 从某一轮另开的会话，与来源共享该轮之前的历史。 |
| 子代理 | 会话在某一轮派出的子任务会话，结束后把结果交回。 |
| 模型账号 / 分组 | 一组模型凭据；分组决定协议与可用模型。 |

## 通用原则（所有领域都适用）
- **G1 安静克制**：几乎无彩色；颜色只用于状态（运行、待审批）与危险操作（红）。
- **G2 辅助信息默认隐藏**：时间、用量、操作按钮悬停才出现。
- **G3 一个功能一个入口**：其他位置只能是跳到这个入口的快捷方式。
- **G4 共享组件**：按钮、菜单、弹层、卡片只用一套；同一份数据（会话树、轮、运行状态、模型能力、滚动位置）只有一处实现。
- **G5 进行中看得见、等待中看得见**：在跑和在等你，都必须一眼看出来。
- **G6 内测阶段不留兼容**：删掉的功能直接删，不保留新旧两套。

## 怎么维护这份定义
1. 每个领域一个文件，按功能分节；每条行为有编号（如 `TREE-3`），写"什么情况、做什么、看到什么"，必要时附一个例子；再写"不做"与"决定（日期、理由）"。
2. 反馈先归到某条行为：没做到 → bug，改代码；要改行为或加行为 → **规格变更**，先改这里、经产品所有者确认，再改实现。
3. 规格变更单独提交，提交信息以 `spec:` 开头。
4. 每条测试名以行为编号开头；检查脚本保证每条行为有测试、每条测试有对应行为。
5. 总量预算：本文件 ≤80 行，每个领域文件 ≤150 行。写不下说明领域该拆，而不是继续加行。
